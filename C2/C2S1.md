# 2.1 Decoder-only Transformer

第 1 章已经把文本变成 Token ID（Token 的编号）。现在要设计一个读取这些编号、预测下一个编号的模型。本章先解释模型由什么模块组成、数据怎样经过这些模块；第 3 章再把它们写成 PyTorch 模型。读本节需要知道向量、矩阵和矩阵乘法的基本意思，不需要会写训练循环。

**从“预测下一个”确定输入和输出。** 沿用 1.1 的手工词表，把“Linux 是一个操作系统”表示成 `[0, 1, 2, 3, 4, 5]`。这是教学编号，并不是实际 LubanTokenizer 的输出。用其中前五个位置作输入，目标向右移动一个位置（也就是后一个位置）：

|  位置 | 输入 Token ID | 本位置应预测的 ID | 预测依据           |
| --: | ----------: | ---------: | -------------- |
|   0 |     0：Linux |       1：空格 | Linux          |
|   1 |        1：空格 |        2：是 | Linux + 空格     |
|   2 |         2：是 |       3：一个 | Linux + 空格 + 是 |
|   3 |        3：一个 |       4：操作 | 前四个 Token      |
|   4 |        4：操作 |       5：系统 | 前五个 Token      |

这就是 Next Token Prediction（预测下一个 Token）。每个位置只能根据当前位置和它前面的内容来猜下一项，这种训练方式叫因果语言建模（Causal Language Modeling）。训练时可以一次送入整段文本并同时计算所有位置，但要用因果遮罩（禁止读取未来位置的规则）挡住后面的答案，具体计算见 [2.2](C2S2.md)。本节先确定模型要预测什么；Loss（衡量预测与正确答案差距的数值）和参数更新放在第 5 章实现。

**先查向量，再计算。** Token ID 是索引，不是可直接比较大小的词义数值。假设词表大小为 V=6，隐藏维度为 H=4，Embedding 就是一张有 6 行、每行 4 个数的可训练表：

$$
E\in\mathbb{R}^{V\times H},\qquad X_t=E[\mathrm{id}_t].
$$

E 是 Embedding 参数，t 是序列位置，H 表示每个位置用多少个特征数来描述。若第 0 行为 `[0.2, -0.1, 0.0, 0.3]`，ID 0 就取这一行；两次出现同一个 ID 会先取同一行，后续 Attention 再结合不同上下文改变表示。表里的初值是随机数，经训练才获得适合任务的表示。

下面的标准库代码可以在 LubanLM 根目录启动 Python 后逐段执行。数值是人为设置的演示，不是训练结果：

```python
embedding = [
    [0.2, -0.1, 0.0, 0.3],
    [0.0,  0.1, 0.2, 0.0],
    [0.4,  0.2, 0.1, 0.0],
    [0.1,  0.0, 0.3, 0.2],
    [0.2,  0.4, 0.0, 0.1],
    [0.0,  0.2, 0.4, 0.1],
]
# input_ids 的每个整数用作 embedding 的行下标。 
input_ids = [0, 1, 2, 3, 4]
# 查表后得到 T=5 个、每个宽 H=4 的隐藏向量。
x = [embedding[token_id] for token_id in input_ids]
print(len(x), len(x[0]))  # 5 4
```

把几条序列（代码中的 ' input_ids = [0, 1, 2, 3, 4] ' 就是一条序列）放在一起处理称为一个 Batch，大小记为 B；每条序列的长度记为 T。输入 ID 的形状是 `[B,T]`，查表后是 `[B,T,H]`。例如 B=2、T=5、H=4 时，模型同时处理两个句子，每个句子有五个位置，每个位置有四个特征。这里的 H 与第 1 章参数公式中的 `hidden_size` 是同一个量。

**Decoder-only 的整体结构。** 本课程参考 Qwen3 Dense Decoder 的核心模块，使用只由解码器块构成的 Transformer：

```text
Token IDs                     [B, T]
  ↓ Embedding
隐藏表示                       [B, T, H]
  ↓ LubanBlock × N
上下文相关的隐藏表示             [B, T, H]
  ↓ Final RMSNorm
归一化后的隐藏表示               [B, T, H]
  ↓ LM Head
Logits                         [B, T, V]
  ↓ 选择最后一个位置的下一个 ID
Next Token                     [B]
```

Decoder-only 不单独建立一个编码器去读取另一段源文本，也不包含与编码器输出交互的交叉注意力。它在已有 Token 前缀上继续生成。每个 Block 都保持 `[B,T,H]` 的外部形状：Attention 让一个位置读取允许范围内的其他位置，前馈网络再变换这个位置的特征。堆叠 N 层让表示经过多次处理；层数不等于输入长度，也不是每层只处理一个 Token。

```
例如，同一个 Token「苹果」：

句子 1：
我 买 了 苹果

句子 2：
这 家 公司 叫 苹果

假设「苹果」的 Token ID 都是 37：

苹果 → 37 → Embedding
            ↓
      [0.2, -0.1, 0.5, 0.3]

刚进入模型时，两处「苹果」的初始 Embedding 相同。

经过 Attention 后：

我 买 了 → 苹果
          ↓
   [0.7, 0.1, -0.2, 0.5]

这 家 公司 叫 → 苹果
              ↓
      [-0.1, 0.8, 0.4, 0.2]

因此：

同一个 Token
    ↓
相同的初始 Embedding
    ↓
读取不同的前文
    ↓
得到不同的隐藏状态

也就是说，Embedding 表示「它是谁」，
而 Transformer 处理后的向量表示
「它在当前上下文中是什么意思」。
```

---
Dense（稠密）表示每个位置都会经过同一套前馈层参数；本课程不使用 MoE（混合专家）那种按输入挑选部分网络的路由机制。RMSNorm 调整特征数值的尺度，RoPE 把位置信息带入注意力计算，GQA 让多组 Query 头共享较少的 K/V 头，SwiGLU 则是前馈网络中的一种计算方式。这些模块会在下一节和 [2.3](C2S3.md) 详细讲解；这里先看它们如何共同构成模型的输入到输出流程。

## RMSNorm 示例

假设某个 Token 当前的隐藏向量为：

$$
h = [2, 4, 6, 8]
$$

这里隐藏维度：

$$
H = 4
$$

先计算均方根 RMS：

$$
RMS(h)
=
\sqrt{
\frac{2^2+4^2+6^2+8^2}{4}
}
$$

$$
=
\sqrt{
\frac{4+16+36+64}{4}
}
$$

$$
=
\sqrt{30}
\approx 5.48
$$

然后用隐藏向量中的每个元素除以 RMS：

$$
\frac{h}{RMS(h)}
=
\left[
\frac{2}{5.48},
\frac{4}{5.48},
\frac{6}{5.48},
\frac{8}{5.48}
\right]
$$

得到：

$$
[0.365,\ 0.730,\ 1.095,\ 1.460]
$$

因此：

```text
原始隐藏向量

[2, 4, 6, 8]

        ↓ RMSNorm

[0.365, 0.730, 1.095, 1.460]
```
如果暂时忽略可训练参数 $g$ 和很小的 $\epsilon$，RMSNorm 可以理解为：

$$ RMSNorm(h) = \frac{h} {\sqrt{\frac{1}{H}\sum_{i=1}^{H}h_i^2}} $$

它的作用可以简单理解为：

> 不改变这个 Token 隐藏向量的大致方向，只把整个向量的数值尺度调整到更加稳定的范围。

---
**从隐藏向量变成词表分数(分数是指模型认为“下一个 Token 是某个候选 Token”的倾向程度)。** LM Head 将 H 维表示映射为 V 个分数：

$$
z_t=h_t W_{\mathrm{out}},\qquad
W_{\mathrm{out}}\in\mathbb{R}^{H\times V}.
$$

 h_t 是经过最后一次 RMSNorm 的行向量，z_t 中的每个数是某个候选 Token 的分数，称为 Logit（复数形式为 Logits）。这些分数可以为负，也不要求相加为 1；沿着词表这一维执行 Softmax，才会把分数转换成总和为 1 的概率：

$$
p_i=\frac{e^{z_i}}{\sum_{j=0}^{V-1}e^{z_j}}.
$$
 ```
 例如，模型读到：

“我今天想吃”

假设词表中只有 3 个候选 Token：

Token 0 = “苹果”
Token 1 = “米饭”
Token 2 = “汽车”

模型经过 Transformer 后得到当前隐藏向量：

h = [1, 2]

LM Head 根据这个隐藏向量，给 3 个候选 Token 打分：

z = [1, 3, -2]

也就是：

苹果：1
米饭：3
汽车：-2

这些数字就是 Logit（分数）。

因为：

3 > 1 > -2

所以模型当前最倾向于：

“米饭”

但这些还不是概率。

经过 Softmax 后，例如变成：

苹果：11%
米饭：88%
汽车：1%

于是模型就更可能生成：

“米饭”

整个过程：

“我今天想吃”
        ↓
Transformer
        ↓
隐藏向量 h
        ↓
LM Head
        ↓
Logits 分数
[1, 3, -2]
        ↓
Softmax
        ↓
概率
[11%, 88%, 1%]
        ↓
选择下一个 Token
“米饭”
 ```


用一个更小的 V=3、H=2 例子独立观察输出层。令 h=[1,2]，输出矩阵的两行是 `[1,0,-1]` 与 `[0,1,0]`，则 z=[1,2,-1]。执行：

```python
import math

# 一个位置经过 Final RMSNorm 后的 H=2 维表示。
h = [1.0, 2.0]
w_out = [[1.0, 0.0, -1.0], [0.0, 1.0, 0.0]]
# 逐列计算 h 与输出矩阵的乘积，得到 V=3 个词表分数。
logits = [sum(h[k] * w_out[k][j] for k in range(2)) for j in range(3)]
# 先减去最大值，数值更稳定且不改变 Softmax 的最终概率。
weights = [math.exp(value - max(logits)) for value in logits]
probs = [value / sum(weights) for value in weights]
print(logits)                         # [1.0, 2.0, -1.0]
print([round(p, 4) for p in probs])    # [0.2595, 0.7054, 0.0351]
print(max(range(3), key=lambda i: probs[i]))  # 1
```

减去最大 Logit 不改变概率比例，却能避免直接计算很大的指数。这个例子选择 ID 1，因为它的分数最高；最高概率只代表模型当前最倾向该 Token，不代表它一定正确。训练要让真实下一 Token 的概率提高，推理则根据既定策略选 Token。

输入 T 个位置时，模型给出 T 组词表分数。训练利用每个位置的预测；生成一个新 Token 时通常取最后一个位置的分数，选出 ID，接到输入末尾，再重复计算。第 8 章会实现这一循环及缓存。第 2 章需要设计的是一个能把 `[B,T]` 映射到 `[B,T,V]`、同时保持因果关系的网络。
