# 2.2 Attention、GQA、QK-Norm 与 RoPE

上一节，我们已经将 Token ID 转换成了向量。现在需要解决一个新问题：**如何让每个 Token 的向量包含与上下文有关的信息？**
例如，假设输入文本为：
`Linux 是一个操作系统`
为了方便理解，我们暂时假设它被切分为 5 个 Token：
`["Linux", "是", "一个", "操作", "系统"]`
这 5 个 Token 按顺序排列，构成一个长度为 5 的序列。每个 Token 在序列中都有自己的**位置（Position）**：
- 位置 1：`Linux`
- 位置 2：`是`
- 位置 3：`一个`
- 位置 4：`操作`
- 位置 5：`系统`
这里的“位置”，指的就是 Token 在输入序列中的排列位置，而不是向量内部某个元素的位置。
当模型处理位置 5 的 `系统` 时，不应该只利用 `系统` 自己的向量，还需要结合前面 `Linux`、`是`、`一个`、`操作` 等 Token 提供的信息。
但这些 Token 对理解当前位置的作用并不一定相同。
**Attention（注意力机制）的核心任务，就是为当前 Token 可以关注的其他 Token 计算权重，再按照权重汇总它们的信息。**
下面从最基本的向量运算开始，逐步理解这个过程。
### 1. 从向量点积开始
首先介绍一个基础数学运算：**点积（Dot Product）**。
假设有两个长度相同的向量：
$$  
a=[a_1,a_2,\ldots,a_n]  
$$
$$  
b=[b_1,b_2,\ldots,b_n]  
$$
它们的点积定义为：
$$  
\boxed{a\cdot b=\sum_{i=1}^{n}a_ib_i}  
$$

也就是把两个向量对应位置的元素相乘，再把所有乘积相加。
例如，定义两个二维向量：
$$  
a=[1,0],\qquad b=[0,1]  
$$
先计算向量 $a$ 与自身的点积：
$$  
a\cdot a=1\times1+0\times0=1  
$$
再计算向量 $a$ 与向量 $b$ 的点积：
$$  
a\cdot b=1\times0+0\times1=0  
$$
可以使用 Python 验证：
``` python
first = [1.0, 0.0]
second = [0.0, 1.0]

def dot(left, right):
    return sum(a * b for a, b in zip(left, right))

print(dot(first, first))   # 1.0
print(dot(first, second))  # 0.0
```

从数学上看，点积与两个向量的长度及夹角有关：
$$  
a\cdot b=|a||b|\cos\theta  
$$
其中：
- $|a|$ 和 $|b|$ 表示向量的长度。
- $\theta$ 表示两个向量之间的夹角。
- $\cos\theta$ 是夹角的余弦值。
在上面的例子中，两个向量的长度都为 1。当 $a$ 与自身进行点积时，夹角为 $0^\circ$，因此结果为 1；当 $a$ 与 $b$ 进行点积时，夹角为 $90^\circ$，因此结果为 0。
**对于长度相同且经过归一化的向量，点积越大，通常意味着它们的方向越接近。**
需要注意，普通点积并不是概率，也不一定介于 0 和 1 之间。在注意力机制中，我们会利用点积计算匹配分数，再通过其他运算将分数转换为权重。
### 2. 为什么需要 Q、K、V？

前面已经知道，点积可以计算两个向量之间的匹配分数。一个自然的想法是：直接使用不同 Token 的输入向量计算点积，再根据分数汇总信息。但这样存在一个限制：**同一个输入向量既要负责寻找相关信息，又要提供被其他 Token 使用的信息。**
为了让模型能够分别学习这些不同的功能，Attention 引入了三组可训练的权重矩阵，将输入向量转换成三种不同的表示。
先考虑一个 Token 的输入向量：
$$  
x=[x_1,x_2,\ldots,x_H]  
$$
其中 $H$ 是输入向量的维度。
定义三个可训练的权重矩阵：
$$  
W_Q,\qquad W_K,\qquad W_V  
$$
让输入向量分别与这三个矩阵相乘：
$$  
\boxed{  
\begin{aligned}  
q=xW_Q,\  
k=xW_K,\  
v=xW_V  
\end{aligned}  
}  
$$
这样，原本的一个输入向量 $x$，就变成了三个向量：
- $q$：Query（查询向量），用于计算当前 Token 对其他 Token 的匹配分数。
- $k$：Key（键向量），用于与其他 Token 的 Query 计算匹配分数。
- $v$：Value（值向量），承载最终要根据注意力权重汇总的信息。
注意，$q$、$k$、$v$ 都是由输入向量经过矩阵乘法得到的，并不是额外输入的三个向量。
为了更直观地理解，假设输入向量为：
$$  
x=[1,0]  
$$
我们手动设置三个 $2\times2$ 矩阵：

$$  
W_Q=  
\begin{bmatrix}  
1&0\\  
0&1  
\end{bmatrix}  
$$
$$  
W_K=  
\begin{bmatrix}  
0&1\\  
1&0  
\end{bmatrix}  
$$
$$  
W_V=  
\begin{bmatrix}  
2&0\\  
0&3  
\end{bmatrix}  
$$
分别计算：
**第一步，生成 Query：**
$$  
q=xW_Q  
$$

$$  
=[1,0]  
\begin{bmatrix}  
1&0\\  
0&1  
\end{bmatrix}  
=[1,0]  
$$
**第二步，生成 Key：**

$$  
k=xW_K  
$$

$$  
=[1,0]  
\begin{bmatrix}  
0&1\\  
1&0  
\end{bmatrix}  
=[0,1]  
$$
**第三步，生成 Value：**

$$  
v=xW_V  
$$

$$  
=[1,0]  
\begin{bmatrix}  
2&0\\  
0&3  
\end{bmatrix}  
=[2,0]  
$$

因此，原来的输入向量：

$$  
x=[1,0]  
$$

经过三次不同的线性变换后，得到：

$$  
\boxed{  
q=[1,0],\quad k=[0,1],\quad v=[2,0]  
}  
$$
这说明，即使输入相同，只要使用不同的权重矩阵，也可以得到不同的向量表示。
在实际模型中，这些权重矩阵不是我们手动设置的，而是在训练过程中不断调整得到的。
### 3. 从单个 Token 扩展到整个序列
前面只考虑了一个 Token。实际输入通常包含多个 Token，因此需要对整个序列执行相同的操作。
假设输入序列共有 $T$ 个 Token，每个 Token 的向量维度为 $H$。
将所有 Token 的向量按行排列，得到输入矩阵：
$$  
X=  
\begin{bmatrix}  
x_1\\  
x_2\\  
\vdots\\  
x_T  
\end{bmatrix}  
$$

其形状为：

$$  
X\in\mathbb{R}^{T\times H}  
$$

如果将 Query 和 Key 的维度设为 $d_k$，Value 的维度设为 $d_v$，那么三个权重矩阵的形状分别为：
$$  
W_Q\in\mathbb{R}^{H\times d_k}  
$$
$$  
W_K\in\mathbb{R}^{H\times d_k}  
$$
$$  
W_V\in\mathbb{R}^{H\times d_v}  
$$

整个序列的投影可以写成：
$$  
\boxed{  
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V  
}  
$$
输出矩阵的形状分别为：
$$  
Q,K\in\mathbb{R}^{T\times d_k}  
$$
$$  
V\in\mathbb{R}^{T\times d_v}  
$$
其中，$Q$、$K$、$V$ 的每一行都对应输入序列中的一个 Token。
这样，我们就为序列中的每一个 Token 都生成了 Query、Key 和 Value。
### 4. Q、K、V 如何参与注意力计算？
现在考虑序列中位置 $i$ 的 Token。
它的 Query 向量为 $q_i$。
对于位置 $j$ 的 Token，它的 Key 向量为 $k_j$。
首先计算二者的点积：
$$  
s_{ij}=q_i\cdot k_j  
$$
这个结果称为**注意力分数（Attention Score）**，表示位置 $i$ 的 Query 与位置 $j$ 的 Key 的匹配程度。如果一次计算整个序列所有位置之间的分数，就可以使用矩阵乘法：
$$  
QK^\mathsf{T}\in\mathbb{R}^{T\times T}  
$$
其中，$K^\mathsf{T}$ 表示矩阵 $K$ 的转置，即交换矩阵的行和列。相乘后的矩阵有 $T$ 行、$T$ 列，每个元素都对应两个位置之间的点积分数。由于向量维度较大时，点积的数值可能较大，模型通常还会将分数除以 $\sqrt{d_k}$，得到缩放后的分数矩阵：
$$  
\boxed{  
S=\frac{QK^\mathsf{T}}{\sqrt{d_k}},  
\qquad S\in\mathbb{R}^{T\times T}  
}  
$$
然后使用 Softmax，将每个位置允许关注的分数转换为**注意力权重（Attention Weight）**：
$$  
\alpha_{ij}=  
\frac{\exp(s_{ij}/\sqrt{d_k})}  
{\sum_{m\in\mathcal A_i}\exp(s_{im}/\sqrt{d_k})}  
$$
其中：
- $s_{ij}$ 表示尚未缩放的点积分数。
- $d_k$ 表示 Query、Key 向量的维度。
- $\exp(x)=e^x$，即以自然常数 $e$ 为底的指数函数。
- $\mathcal A_i$ 表示位置 $i$ 允许关注的位置集合。
- $\alpha_{ij}$ 表示位置 $i$ 分配给位置 $j$ 的注意力权重。
Softmax 会让允许关注的各个位置的权重均为非负数，并且总和为 1。通常，分数越高，对应权重也越大。
不过，**文本生成时还存在一个限制：当前 Token 不能提前看到未来的 Token。**
例如，在序列：
`["Linux", "是", "一个", "操作", "系统"]`
中，当模型处理 `一个` 时，可以利用 `Linux`、`是` 和 `一个` 的信息，但不能提前使用后面的 `操作` 和 `系统`。
因此，需要在 Softmax 之前使用**因果遮罩（Causal Mask）**，将不允许关注的位置对应的分数设置为负无穷。由于：
$$  
e^{-\infty}=0  
$$

这些位置经过 Softmax 后，权重就会变为 0，不参与最终的信息汇总。
最后，利用注意力权重对对应位置的 Value 向量进行加权求和：

$$  
\boxed{  
o_i=\sum_{j\in\mathcal A_i}\alpha_{ij}v_j  
}  
$$

这里的 $o_i$ 就是位置 $i$ 的注意力输出向量。
整个过程可以概括为：
1. 使用 **Query 和 Key 的点积**计算匹配分数。
2. 对分数进行缩放，并使用**因果遮罩**排除未来位置。
3. 使用 **Softmax** 将分数转换为注意力权重。
4. 使用这些权重对 **Value** 进行加权求和，得到包含上下文信息的新向量。

因此，注意力机制并不是简单地将所有 Token 的向量相加，而是让不同位置的信息以不同权重参与计算。这就是 Attention 能够让 Token 表示结合上下文信息的基本原理。

**通过程序验证注意力计算**
前面的公式可以使用 Python 进行数值验证。在 LubanLM 根目录的 PowerShell 中运行：
``` 
python C2\program\2.2\attention_demo.py
```
程序只使用 Python 标准库，按照以下顺序执行计算：
```
Q、K 点积
    ↓
除以 sqrt(d_k)
    ↓
应用因果遮罩
    ↓
Softmax 计算权重
    ↓
对 V 加权求和
    ↓
输出新的向量
```
为了验证遮罩是否真正生效，程序还会将未来位置的 K、V 修改为较大的数值，观察输出是否发生变化。
例如，程序使用从 0 开始的位置编号。对于位置 0 的 Token，因果遮罩只允许它关注自己，因此 Softmax 后自身的权重必然为 1，其输出就是该位置的 Value。在示例数据中，输出应为：
```
[1.0, 0.0]
```

即使修改后面位置的 K、V，只要因果遮罩正确，位置 0 的输出就不会改变。
相反，如果移除遮罩，位置 0 就能够关注未来位置，输出也可能受到未来内容的影响。
这个实验验证了因果遮罩的作用：**保证当前位置的注意力计算不会使用未来 Token 的信息。**
### 5. 从单头注意力到 GQA

前面介绍的注意力计算，可以理解为只有一组 Q、K、V 参与运算。
但实际的大语言模型通常不会只使用一组 Q、K、V，而是将向量划分成多个较小的部分，让它们分别执行注意力计算。
这种独立计算注意力的部分称为**注意力头（Attention Head）**。
为什么要使用多个注意力头？
因为同一段文本中，不同 Token 之间可能存在多种不同的关系。
例如，处理 `Linux 是一个操作系统` 时，模型可能需要关注词语之间的语法关系，也可能需要关注 `Linux` 和 `操作系统` 之间的语义关系。
使用多个注意力头，可以让不同的投影参数分别学习不同的匹配关系，而不必让所有信息都通过同一组 Q、K、V 完成计算。
这种结构称为**多头注意力（Multi-Head Attention，MHA）**。
**多头注意力的矩阵形状**
沿用 C2 课程中的微型模型，假设：
$$  
B=1,\qquad T=5,\qquad H=4  
$$
其中：
- $B$（Batch Size）：一次处理的序列数量。
- $T$（Sequence Length）：每条序列包含的 Token 数量。
- $H$（Hidden Size）：每个 Token 的输入向量维度。

考虑将 4 维向量划分为两个注意力头，每个头负责 2 个特征：
$$  
n_q=2,\qquad d=2  
$$
其中，$n_q$ 表示 Query 头的数量，$d$ 表示每个头的向量维度。
为便于理解，本课程设置每个头的 Q、K、V 维度均为 $d$。
输入张量的形状为：
$$  
X\in\mathbb{R}^{1\times5\times4}  
$$
执行 Q 投影后，得到：
$$  
Q\in\mathbb{R}^{1\times5\times4}  
$$

因为最后的 4 个特征需要分给两个头，所以将其拆分：

$$  
[1,5,4]\rightarrow[1,5,2,2]  
$$

接着调整维度顺序，将注意力头的维度移到序列维度之前：

$$  
\boxed{  
[1,5,2,2]\rightarrow[1,2,5,2]  
}  
$$

现在这个张量可以理解为：

```
Q：[1, 2, 5, 2]
     │  │  │  │
     │  │  │  └── 每个头的特征数 d=2
     │  │  └───── 序列长度 T=5
     │  └──────── Query 头数 n_q=2
     └─────────── Batch Size B=1
```

因此，两个 Query 头可以分别使用自己的 Query 向量计算注意力。

**从 MHA 到 GQA**

在普通多头注意力 MHA 中，每个 Query 头通常都有自己对应的一组 Key 和 Value。

但这里有一个问题：随着注意力头数量增加，模型需要生成和保存的 K、V 数据也会增多。

实际上，多个 Query 头不一定需要使用不同的 K、V。

为了减少这部分开销，可以让多个 Query 头共享同一组 K、V。

根据共享方式，常见的注意力结构有三种：

|方式|Query 头数|K/V 头数|共享方式|
|---|---|---|---|
|MHA（多头注意力）|8|8|每个 Q 头对应一组独立 K/V|
|MQA（多查询注意力）|8|1|所有 Q 头共享一组 K/V|
|GQA（分组查询注意力）|8|2|每 4 个 Q 头共享一组 K/V|

LubanLM 使用的是 **GQA（Grouped-Query Attention，分组查询注意力）**。

以 8 个 Query 头、2 个 K/V 头为例：

```
Query 头                K/V 头

Q0 ───┐
Q1 ───┤
Q2 ───┼─────────────── KV0
Q3 ───┘

Q4 ───┐
Q5 ───┤
Q6 ───┼─────────────── KV1
Q7 ───┘
```

这里：

- Query 头 0～3 共享第 0 组 K/V。
    
- Query 头 4～7 共享第 1 组 K/V。
    

需要注意，虽然多个 Query 头共享 K/V，但它们仍然使用各自的 Query 计算注意力分数，因此**共享 K/V 不意味着这些 Query 头会得到相同的输出**。

对于均匀分组的 GQA，每组 Query 头的数量为：

$$  
\boxed{  
g=\frac{n_q}{n_{kv}}  
}  
$$

其中：

- $n_q$：Query 头数量。
    
- $n_{kv}$：K/V 头数量。
    
- $g$：每组包含的 Query 头数量。
    

因此，$n_q$ 必须能够被 $n_{kv}$ 整除。

回到本课程的微型模型：

$$  
n_q=2,\qquad n_{kv}=1,\qquad d=2  
$$

两个 Query 头共享一个 K/V 头。

此时 Q、K、V 的形状如下：

|对象|线性投影后的形状|拆分注意力头后的形状|
|---|---|---|
|Q|`[1,5,4]`|`[1,2,5,2]`|
|K|`[1,5,2]`|`[1,1,5,2]`|
|V|`[1,5,2]`|`[1,1,5,2]`|

推广到一般情况：

|对象|线性投影后的形状|拆分注意力头后的形状|
|---|---|---|
|Q|`[B,T,n_q*d]`|`[B,n_q,T,d]`|
|K、V|`[B,T,n_kv*d]`|`[B,n_kv,T,d]`|

每个 Query 头会使用所属分组的 K/V 完成注意力计算，得到一个形状为 `[B,T,d]` 的输出。

所有 Query 头的输出沿特征维度拼接，最终得到：

$$  
O_{\mathrm{concat}}\in\mathbb{R}^{B\times T\times(n_qd)}  
$$

为了让 Attention 的输出维度与输入维度保持一致，还需要经过一个可训练的输出投影矩阵：

$$  
W_O\in\mathbb{R}^{(n_qd)\times H}  
$$

计算为：

$$  
\boxed{  
O=O_{\mathrm{concat}}W_O  
}  
$$

最终输出形状为：

$$  
O\in\mathbb{R}^{B\times T\times H}  
$$

本课程设置 $H=n_qd$，因此多个头拼接后刚好具有 $H$ 个特征，但仍然会执行输出投影。

注意，**多头注意力是将各头输出拼接后进行线性投影，而不是简单地对所有头的输出求平均。**

**GQA 为什么能够节省显存？**

前面介绍了 GQA 可以减少 K/V 的数量，但这有什么实际意义？

对于大语言模型，生成文本时通常是一个 Token 接一个 Token 地生成。

例如，模型已经处理了：

`Linux 是一个`

接下来准备生成新的 Token。

此时，模型需要利用前面已经处理过的 Token 计算注意力。如果每生成一个 Token，都重新计算此前所有 Token 的 K、V，就会产生大量重复运算。

因此，模型通常会将已经计算好的 K、V 保存下来。生成下一个 Token 时，只需要计算新 Token 的 K、V，并复用之前保存的结果。

这个机制称为**键值缓存（KV Cache）**。

KV Cache 保存的是注意力计算中需要复用的 K、V 张量，而不是最终生成的文本。它会随着生成的 Token 数量增加而增长。

由于 GQA 减少了 K/V 头的数量，因此也能减少 KV Cache 的内存占用。

忽略额外管理开销，标准全量 KV Cache 的字节数可以写成：

$$  
\boxed{  
M_{KV}=2\times B\times L\times T\times n_{kv}\times d\times s  
}  
$$

其中：

- $2$：分别存储 K 和 V。
    
- $B$：Batch Size。
    
- $L$：Transformer 层数。
    
- $T$：缓存的 Token 数量。
    
- $n_{kv}$：每层的 K/V 头数。
    
- $d$：每个 K/V 头的维度。
    
- $s$：每个元素占用的字节数。
    

例如，假设：

$$  
B=1,\quad L=1,\quad T=2048,\quad d=64,\quad s=2  
$$

只改变 K/V 头数量，得到：

|注意力方式|K/V 头数|KV Cache 大小|
|---|---|---|
|MHA|8|4 MiB|
|GQA|2|1 MiB|
|MQA|1|0.5 MiB|

其中：

$$  
1\ \mathrm{MiB}=1048576\ \mathrm{bytes}  
$$

可以看到，在其他参数相同的情况下，GQA 将 K/V 头数从 8 减少到 2，KV Cache 的大小也减少为原来的四分之一。

不过，这并不意味着整个 Attention 的计算速度会提高四倍，因为各个 Query 头仍然需要计算自己的注意力分数和输出。

第 3 章为了更容易展示计算过程，会先采用显式展开分组 K/V 的实现方式，让多个 Query 头获得各自需要的 K/V。真正部署时，可以使用避免重复存储 K/V 的高效实现。

KV Cache 的实际更新方法将在第 8 章实现。

### 6. QK-Norm：控制 Q 和 K 的数值尺度

前面介绍的 Attention 使用 Q 和 K 的点积计算注意力分数。

但是，点积不仅与两个向量的方向有关，还与它们的长度有关。

回顾点积公式：

$$  
q\cdot k=|q||k|\cos\theta  
$$

假设：

$$  
q=[1,2],\qquad k=[2,1]  
$$

它们的点积为：

$$  
q\cdot k=1\times2+2\times1=4  
$$

如果将 $q$ 的所有分量同时放大 10 倍：

$$  
q'=[10,20]  
$$

那么：

$$  
q'\cdot k=10\times2+20\times1=40  
$$

可以看到，即使 $q$ 的方向没有变化，点积也从 4 增加到了 40。

而注意力分数需要经过 Softmax。当分数之间的差距变大时，Softmax 的输出可能变得更加集中，让少数位置获得很大的权重。

为了减小 Q、K 整体幅度变化对注意力计算的影响，LubanLM 在点积之前对 Q 和 K 分别执行归一化。

这种方法称为 **QK-Norm（Query-Key Normalization）**。

本课程使用 RMSNorm（Root Mean Square Normalization，均方根归一化）实现 QK-Norm。

**RMSNorm 的计算过程**

首先考虑一个向量：

$$  
q=[3,4]  
$$

RMSNorm 的第一步，是计算向量的均方根（Root Mean Square，RMS）。

对于长度为 $d$ 的向量：

$$  
q=[q_1,q_2,\ldots,q_d]  
$$

均方根的计算公式为：

$$  
\boxed{  
\operatorname{RMS}(q)=  
\sqrt{\frac{1}{d}\sum_{r=1}^{d}q_r^2}  
}  
$$

计算过程就是：

1. 将每个分量平方。
    
2. 计算所有平方数的平均值。
    
3. 对平均值开平方。
    

对于 $q=[3,4]$：

$$  
\operatorname{RMS}(q)  
=\sqrt{\frac{3^2+4^2}{2}}  
$$

$$  
=\sqrt{\frac{9+16}{2}}  
=\sqrt{12.5}  
\approx3.5355  
$$

接下来，用这个均方根除以向量中的每一个分量：

$$  
\widehat q=  
\left[  
\frac{3}{3.5355},  
\frac{4}{3.5355}  
\right]  
$$

得到：

$$  
\boxed{  
\widehat q\approx[0.8485,1.1314]  
}  
$$

如果将原来的向量放大 10 倍：

$$  
q'=[30,40]  
$$

其均方根也会放大 10 倍：

$$  
\operatorname{RMS}(q')\approx35.3553  
$$

因此：

$$  
\widehat q'=  
\left[  
\frac{30}{35.3553},  
\frac{40}{35.3553}  
\right]  
$$

结果仍然约为：

$$  
\widehat q'\approx[0.8485,1.1314]  
$$

**这说明，在忽略数值修正项时，RMSNorm 能够消除向量整体正比例放大带来的影响。**

需要注意，RMSNorm 与普通的单位长度归一化不同。它让向量各分量平方的平均值接近 1，并不要求向量的欧几里得长度等于 1。

在实际模型中，为了避免分母为零，并保留可学习的特征缩放能力，RMSNorm 还会加入两个部分：

- $\epsilon$：一个很小的正数，用于保证数值计算安全。
    
- $\gamma$：可训练的缩放向量，用于调整归一化后各个特征的尺度。
    

因此，完整的 QK-Norm 计算为：

$$  
\boxed{  
\widehat q=  
\frac{q}{  
\sqrt{\frac{1}{d}\sum_{r=1}^{d}q_r^2+\epsilon}  
}  
\odot\gamma_Q  
}  
$$

$$  
\boxed{  
\widehat k=  
\frac{k}{  
\sqrt{\frac{1}{d}\sum_{r=1}^{d}k_r^2+\epsilon}  
}  
\odot\gamma_K  
}  
$$

其中，$\odot$ 表示对应位置的元素相乘。

例如：

$$  
[1,2]\odot[3,4]=[3,8]  
$$

Q 和 K 使用各自的归一化参数，分别进行计算。

在本课程采用的结构中，每层所有 Query 头共享一条长度为 $d$ 的 $\gamma_Q$，所有 Key 头共享另一条长度为 $d$ 的 $\gamma_K$。

归一化沿每个注意力头最后的 $d$ 个特征进行，不混合不同 Token 的信息，也不对 Value 执行这一步归一化。

因此，QK-Norm 的计算位置是：

```
Q 投影 → 拆分注意力头 → RMSNorm ──┐
                                  ├→ 后续注意力计算
K 投影 → 拆分注意力头 → RMSNorm ──┘

V 投影 → 拆分注意力头 → 不执行 QK-Norm
```

QK-Norm 不能保证所有情况下的训练都稳定，但可以减小 Q、K 的整体数值尺度变化对注意力分数的影响。后续计算仍然会保留点积除以 $\sqrt d$ 的缩放步骤。

下一节将介绍的 Transformer Block 也会使用 RMSNorm，不过归一化的位置和对象有所不同。

### 7. RoPE：让注意力感知 Token 的位置

现在，Attention 已经可以利用 Q 和 K 计算匹配分数，也可以使用 QK-Norm 调整数值尺度。

但是还有一个问题：**模型如何区分 Token 在序列中出现的位置？**

例如，考虑两个输入：

`Linux 支持 Python`

`Python 支持 Linux`

它们包含相同的几个 Token，但排列顺序不同，表达的含义也不同。

如果只有普通的 Q、K、V 投影，而没有任何位置信息，那么相同的 Token 在相同输入表示下仍然会得到相同的 Q、K、V。

仅靠这些投影，模型就无法直接知道一个 Token 出现在序列的什么位置，以及它与其他 Token 相隔多远。

为了让 Attention 的匹配分数包含位置信息，LubanLM 使用 **RoPE（Rotary Position Embedding，旋转位置编码）**。

RoPE 的基本思想是：

**根据 Token 所处的位置，对 Query 和 Key 向量进行旋转，使它们的点积不仅与向量内容有关，也与 Token 之间的位置关系有关。**

**从二维向量旋转开始**

首先考虑一个二维向量：

$$  
x=[1,0]  
$$

在二维平面中，可以把它看作一个从原点指向 $(1,0)$ 的箭头。

如果将它逆时针旋转 $90^\circ$，就会得到：

$$  
x'=[0,1]  
$$

旋转前后，向量的长度保持不变，但方向发生了变化。

因此，如果使用某个固定向量与旋转前后的向量计算点积，就可能得到不同的结果。

这正是 RoPE 利用的数学性质。

对于二维向量：

$$  
x=  
\begin{bmatrix}  
x_1\  
x_2  
\end{bmatrix}  
$$

逆时针旋转角度 $\phi$ 的计算公式为：
$$
\begin{bmatrix}  
x_1\cos\phi-x_2\sin\phi\\  
x_1\sin\phi+x_2\cos\phi  
\end{bmatrix}   
$$

其中，$R(\phi)$ 表示旋转操作，$\phi$ 表示旋转角度。

例如，当 $\phi=90^\circ$ 时：

$$  
\cos90^\circ=0,\qquad\sin90^\circ=1  
$$

代入：
$$
\begin{bmatrix}  
0\  
1  
\end{bmatrix}  
$$

与前面得到的结果一致。

**RoPE 如何将位置转换为旋转角度？**

RoPE 不会简单地让所有 Token 都旋转固定的 $90^\circ$。

它会根据 Token 在序列中的位置，计算对应的旋转角度。

假设某个 Token 的位置编号为 $m$，某一对坐标使用的旋转频率为 $\theta$，则旋转角度为：

$$  
\boxed{  
\phi=m\theta  
}  
$$

这里：

- $m$：Token 的位置编号，程序中通常从 0 开始。
    
- $\theta$：该坐标对所使用的旋转频率。
    
- $\phi$：实际旋转角度，计算时使用弧度。
    

例如，假设某一对坐标的频率为：

$$  
\theta=\frac{\pi}{2}  
$$

那么不同位置的旋转角度分别为：

|Token 位置 $m$|旋转角度 $m\theta$|
|---|---|
|0|0°|
|1|90°|
|2|180°|
|3|270°|

这个例子只是为了方便理解。实际模型会使用多组不同的旋转频率，而不是让所有坐标都按照同一个角度变化。

对于维度为 $d$ 的注意力头，RoPE 通常将坐标划分为 $d/2$ 对，每一对坐标分别执行二维旋转。

一种常见的频率设置为：

$$  
\boxed{  
\theta_r=\mathrm{base}^{-\frac{2r}{d}}  
}  
$$

其中：

- $r$：坐标对的编号，从 0 到 $d/2-1$。
    
- $d$：注意力头的维度。
    
- $\mathrm{base}$：模型配置的旋转频率基数。
    

不同坐标对具有不同的频率，因此会随着位置变化产生不同的旋转角度。

在这里，$d$ 需要是偶数，才能将全部特征划分为二维坐标对。

**为什么旋转能够表示相对位置？**

假设两个 Token 分别位于位置 $m$ 和位置 $n$。

它们对应的 Query 和 Key 向量分别为 $q$ 和 $k$。

经过 RoPE 后：

$$  
q'=R(m\theta)q  
$$

$$  
k'=R(n\theta)k  
$$

这里先将向量看作列向量，以便使用旋转矩阵进行推导。

Attention 计算的是旋转后的 Query 与 Key 的点积：

$$  
(q')^\mathsf{T}k'  
$$

将旋转公式代入：

$$  
=(R(m\theta)q)^\mathsf{T}(R(n\theta)k)  
$$

利用矩阵转置性质：

$$  
=q^\mathsf{T}R(m\theta)^\mathsf{T}R(n\theta)k  
$$

二维旋转矩阵具有以下性质：

$$  
R(a)^\mathsf{T}=R(-a)  
$$

$$  
R(a)R(b)=R(a+b)  
$$

因此：

$$  
=q^\mathsf{T}R(-m\theta)R(n\theta)k  
$$

最后得到：
$$
q^\mathsf{T}R((n-m)\theta)k 
$$

观察右侧，可以发现一个重要的结果：

**旋转后的点积与两个 Token 的位置差 $n-m$ 有关。**

例如，当两个 Token 的位置相差 1 时，点积中包含的相对旋转角度为 $\theta$；当位置相差 3 时，相对旋转角度就变成 $3\theta$。

这意味着，Attention 不仅能够通过 Q 和 K 判断两个 Token 的内容是否匹配，还能利用旋转后的点积感知它们之间的位置关系。

这就是 RoPE 的核心作用。

需要注意，RoPE 只是将位置信息引入注意力计算，并不会阻止模型关注未来位置。因此，**即使使用 RoPE，因果遮罩仍然必不可少。**

另外，RoPE 需要固定头内坐标的配对方式。例如，相邻维度配对与前后半维配对属于不同的排列约定。训练、模型转换和推理时必须保持相同的约定，否则即使权重数值没有变化，也可能得到不同的计算结果。

### 8. 将这些操作组合成完整的 Attention

到这里，我们已经分别了解了：

- **Attention**：利用 Query 和 Key 计算注意力权重，并对 Value 加权求和。
    
- **GQA**：让多个 Query 头共享 K/V，减少 K/V 投影参数和 KV Cache 的存储开销。
    
- **QK-Norm**：在点积之前归一化 Q 和 K，减小整体数值尺度变化的影响。
    
- **RoPE**：根据 Token 位置旋转 Q 和 K，让注意力分数包含位置关系。
    

这些机制并不是相互独立地输出结果，而是在同一次注意力计算中按顺序组合使用。

本课程采用的 Attention 计算流程如下：

```
                   输入 X
                     │
          ┌──────────┼──────────┐
          │          │          │
       Q 投影     K 投影      V 投影
          │          │          │
       拆分头      拆分头      拆分头
          │          │          │
       QK-Norm    QK-Norm       │
          │          │          │
         RoPE       RoPE        │
          │          │          │
          └─────┬────┘          │
                │               │
          Q 与分组 K 点积        │
                │               │
           除以 sqrt(d)         │
                │               │
            因果遮罩            │
                │               │
             Softmax            │
                │               │
                └───────┬───────┘
                        │
                 对分组 V 加权求和
                        │
                  拼接 Query 头
                        │
                    输出投影
                        │
                   Attention 输出
                     [B,T,H]
```

需要特别注意，前面为了方便学习，是先介绍基础 Attention，再逐步添加 GQA、QK-Norm 和 RoPE。

但在真正的计算中，QK-Norm 和 RoPE 都发生在 Q、K 点积之前。

QK-Norm 和 RoPE 的顺序也不能随意交换：本课程先进行 QK-Norm，再应用 RoPE。

最终，Attention 的输入与输出形状保持一致：

$$  
\boxed{  
[B,T,H]\rightarrow[B,T,H]  
}  
$$

但输出向量已经不再只是对应 Token 的原始表示，而是融合了当前 Token 可以关注的上下文信息。

本节的计算顺序可以对照 [Hugging Face Qwen3 参考实现](https://github.com/huggingface/transformers/blob/v4.57.6/src/transformers/models/qwen3/modular_qwen3.py)。

下一节，我们将进一步学习 Transformer Block，了解如何将 Attention 与 RMSNorm、前馈网络和残差连接组合起来，构建一个完整的 Transformer 计算模块。
