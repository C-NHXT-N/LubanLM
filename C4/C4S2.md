# 4.2 数据清洗与去重

> 2026-10-16 路线更新：50M 已完成 5B Token 预训练及一轮 SFT，作为从零训练的教学案例保留；现有结果未证明可靠通用问答能力。第7章起转向成熟模型 LoRA 微调与部署，扩容另作可选实验。当前状态见 [项目状态](../PROJECT_STATUS.md)。

> 实验入口：先完成[低成本必修实验](../docs/低成本必修实验.md)。本节大规模数据与50M命令用于历史研究，需要对应的旧数据版本；目录采用workspace_env.ps1设置，使用已激活的原生环境，不是成熟模型LoRA入口。

从上一节得到一篇文章后，先看模型最终会读到什么。下面两条字符串表面不同，却可能来自同一份文本：

```python
first = "Linux 是一个操作系统。\r\n\r\n它管理内存。"
second = "Linux 是一个操作系统。\n\n它管理内存。"
print(first == second)  # False：换行编码不同。
```

如果直接对原始字节求哈希，它们会被当成两份文章。清洗代码先把 Windows 的 `\r\n`、旧式 `\r` 统一成 `\n`，再删除不用于正文的控制字符，并把连续三个以上换行压成两个。空格和普通换行仍有内容作用，不能为了“干净”全部删除；代码缩进、单词边界和段落结构都依赖它们。

Unicode 的 NFC 规范化把等价字符表示合成一致形式。例如一个带重音字母可能由单字符表示，也可能由基础字母加组合符号表示。NFC 处理的是这种编码等价关系，不负责翻译简繁体，也不会把不同意义的词强行合并。

把清洗函数应用到当前例子：

```python
from data.prepare import clean

a = clean(first)
b = clean(second)
print(a)
assert a == b
```

这段代码应在项目根目录的 Python 环境运行。输出仍有两个段落，现在同一正文得到了同一字符串。接着用 SHA256 把正文转换为固定长度的摘要：

```python
import hashlib

digest_a = hashlib.sha256(a.encode("utf-8")).hexdigest()
digest_b = hashlib.sha256(b.encode("utf-8")).hexdigest()
assert digest_a == digest_b
```

摘要适合查重，因为无需为每次比较逐字扫描两篇长文章。程序把已保留的摘要放进集合，后续再遇到相同摘要便跳过。这里采用的是**清洗后精确去重**：两个版本只差一句话，就仍会保留。它没有执行近似去重，报告里也不能写成“已经消除了所有重复内容”。

本课程另外过滤少于 80 字符或超过 100,000 字符的文章。太短的片段可能没有足够上下文，特别长的文章则会增加这次小规模准备的负担。长度阈值是教学流程的处理规则，不是普遍适用的质量标准。把字符数换成 Token 数后，长度还会改变，因此编码阶段会继续统计。

正文中若直接出现 `<pad>`、`<bos>` 或 `<eos>` 的可见拼写，也会被过滤。这些字符串已经被 Tokenizer 注册为特殊 Token；把它们当普通文章内容编码，可能提前插入结束边界。过滤的是协议冲突，不是因为这些文章一定没有价值。

训练集和验证集在去重后划分。程序用内容摘要前八位的整数对 100 取余，小于 2 的文档进入验证集，其余进入训练集。这使同一篇正文无论下载顺序如何变化，都进入同一侧。实际文档数通常接近 98:2，但不会精确等于这个比例；两侧 Token 数更不必保持这个比例。

完整处理见 [prepare.py](../data/prepare.py)。重复运行 `python -m data.prepare` 会复用本地原始文件，然后按相同规则重新处理，不重复下载另一版文本。若要更换下载上限或来源版本，应保留旧记录并使用新数据目录，避免把不同原始数据混在一个版本名下。处理完成后查看 `$env:LUBAN_RUNS\reports\data_stats.json` 中的长度过滤数、重复数和两侧文档数，再进入编码。
