# 4.3 Tokenization 与训练数据格式

> 2026-10-16 路线更新：50M 已完成 5B Token 预训练及一轮 SFT，作为从零训练的教学案例保留；现有结果未证明可靠通用问答能力。第7章起转向成熟模型 LoRA 微调与部署，扩容另作可选实验。当前状态见 [项目状态](../PROJECT_STATUS.md)。

> 实验入口：先完成[低成本必修实验](../docs/低成本必修实验.md)。本节大规模数据与50M命令用于历史研究，需要对应的旧数据版本；目录采用workspace_env.ps1设置，使用已激活的原生环境，不是成熟模型LoRA入口。

清洗后的一行 JSON 仍然包含文字。模型需要整数，所以本节把文章编码成 ID，并安排训练时如何取出一段输入与目标。先用人为指定的短序列看清位移关系：

```python
import torch

ids = torch.tensor([[11, 28, 35, 9, 2]])
x = ids[:, :-1]
y = ids[:, 1:]
print(x.tolist())  # [[11, 28, 35, 9]]
print(y.tolist())  # [[28, 35, 9, 2]]
```

本例四个输入位置分别预测后面的四个 ID。`x` 和 `y` 都是 `[B,T]`，其中 `B=1` 表示一条序列，`T=4` 表示四个预测位置。一次样本实际需要 `T+1` 个 ID。训练循环只在这里错开一次，模型 `forward` 返回原始输出分数，不再自动错开标签。

正式编码前，复用第 1 章程序训练并比较三个词表。在项目根目录的 PowerShell 执行：

```powershell
. .\scripts\workspace_env.ps1
foreach ($vocab in 16000,32000,40000) {
    python .\C1\program\1.3\train_tokenizer.py --input $env:LUBAN_DATA\processed\tokenizer-train.jsonl --vocab-size $vocab --output "$env:LUBAN_DATA\tokenizers\vocab-$vocab"
    python .\C1\program\1.3\evaluate_tokenizer.py --tokenizer "$env:LUBAN_DATA\tokenizers\vocab-$vocab" --input $env:LUBAN_DATA\processed\tokenizer-eval.jsonl --report-dir "$env:LUBAN_RUNS\reports\tokenizer-$vocab" --hidden-size 512
}
python -m data.tokenize
```

主流程使用目标 32k 的版本，模型配置依据它的实际词表大小生成。目标值只是 BPE 训练器的上限；语料中的合并候选不足时，实际词表会更小。比较时同时看中文压缩长度、英文与代码诊断长度、往返还原和 Embedding 参数量，不能仅凭更大的词表就断言模型效果更好。

本机首次把全部正文交给 BPE 时发生系统内存分配失败。当前准备程序改为每隔一篇训练文档取前 512 字符，并设八百万字符总上限，三组词表都使用这份相同的有界文本。完整文章仍用于预训练，验证文档仍不进入 BPE 学习。这个限制控制分词器训练的临时内存，也会影响它能看到的片段分布，报告中保留抽取规则与实际字符数。

每篇文章编码后追加一个 EOS。假设两篇文章分别产生 `[11,28,35]` 与 `[7,19]`，拼接结果就是 `[11,28,35,2,7,19,2]`。EOS 告诉模型前一篇正文结束，打包时仍允许后篇看到前篇的内容；本课程没有加“文章之间互相不可见”的块遮罩。这样的上下文策略必须写进数据记录，方便解释训练行为。

打包数据按约两百万 Token 分成 `.bin` 文件。词表不超过 65,536 时，一个 ID 用 `uint16` 的两个字节存储；更大时改用 `uint32`。磁盘 dtype 用于节省空间，送进 Embedding 前仍转换为 `torch.long`。不能把小整数存储类型直接当成 PyTorch Embedding 的输入类型。

每个分片的 `manifest.json` 保存 dtype、长度、文件路径、SHA256 和 Tokenizer 哈希。读取时使用内存映射（memory mapping），让程序访问文件的一段，而不是先把整个语料复制到内存。训练随机选择一个合法起点，从该分片取 `T+1` 个连续 ID；分片末尾不足一段时不会拼接到另一文件，避免读取越界。

读取与切分实现见 [batches.py](../training/batches.py)，编码与统计见 [tokenize.py](../data/tokenize.py)。当前循环直接从内存映射采样，相当于采用单进程批次读取；Windows 下不需要启动额外 DataLoader worker。将来需要 `DataLoader` 时，先设置 `num_workers=0` 检查结果，再研究多进程的启动和内存成本。

旧50M的SFT数据也在这一步编码，保留逐条问答及回答掩码，不和普通文章一样随意拼接。第7章会用成熟模型重新追踪标签为何出现 `-100`；届时文本必须按成熟模型原生Tokenizer重新编码，不能复用这里的Token ID。现在检查两侧 Token 总数与词表大小，下一节把这些文件整理成可以复用的数据版本。
