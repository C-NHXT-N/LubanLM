# 4.1 LLM 到底需要什么数据

> 2026-10-16 路线更新：50M 已完成 5B Token 预训练及一轮 SFT，作为从零训练的教学案例保留；现有结果未证明可靠通用问答能力。第7章起转向成熟模型 LoRA 微调与部署，扩容另作可选实验。当前状态见 [项目状态](../PROJECT_STATUS.md)。

> 实验入口：先完成[低成本必修实验](../docs/低成本必修实验.md)。本节大规模数据与50M命令用于历史研究，需要对应的旧数据版本；目录采用workspace_env.ps1设置，使用已激活的原生环境，不是成熟模型LoRA入口。

第 3 章的模型已经能把一串 ID 变成下一位置的分数，但那些分数来自随机权重。现在要给它准备真正能够学习的文本。先把两条记录放在一起看：

```json
{"text": "Linux 是一个操作系统。它管理进程和内存。"}
{"user": "Linux是什么？", "assistant": "Linux是一类开源操作系统的内核。"}
```

第一条只包含一段文章。模型读到“Linux 是一个”时，目标是预测原文接下来的内容；读到“它管理”时，目标又变成后面的词。这种从普通文本产生监督目标的训练叫预训练（Pretraining）。原文中的位置顺序已经提供了目标，不需要人为给每个位置写答案。

第二条明确区分提问者和回答者。问题本身属于输入条件，助手回答才是我们希望模型模仿的部分。这种用指令与回答继续训练的方法叫监督微调（Supervised Fine-Tuning，SFT）。两种训练可以使用同一个语言模型和交叉熵损失，但数据格式与哪些位置参与计分不同。文章里出现问号，也不会自动变成适合聊天的训练样本。

本课程采用一个主要预训练来源：[Wikimedia Wikipedia 的中文快照](https://huggingface.co/datasets/wikimedia/wikipedia)，配置名为 `20231101.zh`。记录中的 `id`、`title`、`url` 和 `text` 分别保存文章编号、标题、原页面和正文。下载时固定数据仓库的 revision，也就是本次使用的版本提交号；之后即使仓库更新，也能知道这次文本来自哪一版。

公开可下载不等于没有使用条件。数据卡列出 CC-BY-SA 3.0 与 GFDL，文章 URL 和数据来源因此要保留。当前教学流程只在本地处理文本，不把原始文章打包成新的公开下载。本次先顺序读取最多 30,000 篇文档，这只是有界教学样本，不能代表全部中文 Wikipedia 的主题分布。

SFT 的主要来源是 [OpenAssistant/oasst1](https://huggingface.co/datasets/OpenAssistant/oasst1)。它保留消息编号、父消息编号、角色、语种和人工审核状态，可以找到一条中文用户消息及其中文助手回复。项目数据卡标注 Apache-2.0。本课程选人工审核通过、没有删除、没有合成标记的父子问答；同一个问题有多个答案时，优先取排名较好的回复。

在项目根目录打开 PowerShell，先选择环境，再运行下载与初步处理：

```powershell
. .\scripts\workspace_env.ps1
python -m data.prepare --documents 30000 --sft-pairs 2000
```

完整程序见 [数据准备代码](../data/prepare.py)。Wikipedia 原始记录保存到 D 盘数据目录，清洗后的正文保存成 JSONL，即每行一条 JSON；OASST 问答另存，不把它混进预训练文章。`sources.yaml` 记录来源、revision、许可和文件哈希，`data_stats.json` 记录实际数量。`2000` 是上限，不是保证会找到的合格样本数。

Tokenizer 的训练集从预训练的训练侧文档产生，验证侧不参与学习合并规则。英文与代码诊断样例只用于检查分词和还原，不能据此声称正式预训练采用了某种中英代码混合比例。下一节先检查文章有没有重复、乱码、过短正文和特殊标记，再把文字交给 Tokenizer。
