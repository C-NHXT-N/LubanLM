# 1.2 从字符 Tokenizer 到 BPE

本节先运行一个字符级 Tokenizer，再一步步跟踪 BPE（Byte Pair Encoding，常译为字节对编码）的训练和编码过程。练习语料只有 `abab` 和 `abac`，可以手算每一轮相邻 Token 的组合。这里先把字符当作基本单位来讲解算法；到 [1.3](C1S3.md)，再把文本转成字节后学习合并规则。

先从字符级词表开始。完整实现见 [character_tokenizer.py](program/1.2/character_tokenizer.py)，BPE 实现见 [teaching_bpe.py](program/1.2/teaching_bpe.py)。程序遍历训练文本，收集字符并排序，再按排序后的顺序分配 ID：

```python
# 先去重再排序，保证同一训练语料每次都得到相同 ID 顺序。
alphabet = sorted(set("".join(texts)))
# 字典保存“字符 Token → Token ID”的查表关系。
token_to_id = {token: token_id for token_id, token in enumerate(alphabet)}
```

对 `texts = ["abab", "abac"]`，词表是 `['a', 'b', 'c']`，对应 ID 为 0、1、2。字符级 `encode` 逐个查表；如果输入包含词表中没有的字符，程序先找出这些字符并报错。它不会悄悄替换或丢弃字符，因为那会让编码信息无法还原。在 LubanLM 根目录运行[字符 Tokenizer 与 BPE 示例](program/1.2/demo.py)，只需要 Python 标准库：

```powershell
python C1\program\1.2\demo.py
```

示例将 `abab` 编码成 `[0, 1, 0, 1]`，解码后仍是 `abab`；最后捕获教学 BPE 对未见字符 `z` 抛出的 `ValueError`，打印“未见字符检查”。字符级方法也会拒绝未见字符。字符级方法的优点是规则直观，缺点是序列长，并且遇到未见字符就无法编码。接下来让常见的相邻片段合并，以减少 Token 数。

BPE 的每一轮都会查看当前序列里哪些 Token 紧挨着出现，并统计这些“相邻 Token 对”。最开始，每个字符就是一个 Token：

```text
abab → a b a b
abac → a b a c
```

相邻对是两个紧挨着的 Token，且左右顺序也算在内；例如 `(a, b)` 和 `(b, a)` 是不同的相邻对。同一对在所有训练文本中出现几次，就把这些次数加起来。第一轮统计结果是：

|相邻对|计数|来源|
|---|---:|---|
|`(a, b)`|3|`abab` 中 2 次，`abac` 中 1 次|
|`(b, a)`|2|两条文本各 1 次|
|`(a, c)`|1|`abac` 中 1 次|

因此第一轮合并 `(a, b)`，产生新 Token `ab`。程序从左向右、不重叠地替换这对 Token。更新后的两条序列为 `ab ab` 与 `ab a c`。第二轮再次对更新后的序列计数：

|  轮次 | 本轮开始的训练序列           | 本轮相邻对及计数                         | 选择的合并            | 替换后的序列           |
| --: | ------------------- | -------------------------------- | ---------------- | ---------------- |
|   1 | `a b a b`；`a b a c` | `(a,b):3`，`(b,a):2`，`(a,c):1`    | `(a,b) → ab`     | `ab ab`；`ab a c` |
|   2 | `ab ab`；`ab a c`    | `(ab,ab):1`，`(ab,a):1`，`(a,c):1` | `(a,c) → ac`     | `ab ab`；`ab ac`  |
|   3 | `ab ab`；`ab ac`     | `(ab,ab):1`，`(ab,ac):1`          | `(ab,ab) → abab` | `abab`；`ab ac`   |
|   4 | `abab`；`ab ac`      | `(ab,ac):1`                      | `(ab,ac) → abac` | `abab`；`abac`    |

第二轮出现并列。教学实现按 Token 的 Unicode 顺序作稳定的决胜：`(a,c)` 排在 `(ab,a)` 与 `(ab,ab)` 前，因此选择 `(a,c)`。第三轮的两个计数也相同，此时 `(ab,ab)` 排在 `(ab,ac)` 前。真实 BPE 实现也需要确定合并顺序，但具体并列规则由所用训练器决定。

统计和实际替换的计数方式需要区分。例如 `aaaa` 中相邻对 `(a,a)` 有 3 个起始位置，因此统计频次为 3；从左向右执行一次非重叠合并时，先合并前两个 `a`，再合并后两个，结果是 `aa aa`，本轮实际合并 2 次。下一轮才能把 `(aa,aa)` 合并为 `aaaa`。因此频次用于挑选规则，不代表一次替换一定按该计数生成同样数量的新 Token。

相邻对统计对应程序里的 `Counter.update`：

```python
# pairs 的键是二元组，值是该相邻对在全部当前序列中的出现次数。
pairs = Counter()
for sequence in sequences:
    # 将序列与去掉首项后的序列错开一位，得到全部相邻 Token 对。
    pairs.update(zip(sequence, sequence[1:]))
 
```

`zip(sequence, sequence[1:])` 将序列和去掉首项的序列对齐，产生所有相邻二元组；`Counter` 汇总频次。选择键先按负频次升序，因此频次最高者优先；频次相同再按 pair 本身排序。完成计数后，合并函数从左到右扫描，只有遇到选中的相邻对时才拼成一个 Token，并跳过这两个原 Token：

```python
if index + 1 < len(sequence) and (sequence[index], sequence[index + 1]) == pair:
    # 命中后消费两个旧 Token，保证本轮合并不重叠。
    merged.append(sequence[index] + sequence[index + 1])
    index += 2
else:
    # 不命中时保留当前位置的 Token，并向右移动一个位置。
    merged.append(sequence[index])
    index += 1
```

训练时反复执行“统计次数→选出次数最多的一对→合并”，直到达到指定轮数，或序列里已没有可合并的相邻对。原始字符和每次合并产生的新片段会一起放进词表。对本例，最终词表依次包含 `a`、`b`、`c`、`ab`、`ac`、`abab`、`abac`；ID 从 0 开始，所以 `abab` 的 ID 是 5，`abac` 的 ID 是 6。配套程序会逐轮打印统计次数、选中的合并和最终词表，方便把实际输出与上表对照。

训练完成后，编码不再重新统计语料，而是按已保存的合并顺序处理新文本。例如 `abaca` 本身不在训练语料中，但它只包含已知字符：先按第一条规则把 `a b` 合成 `ab`，再按第二条规则把后面的 `a c` 合成 `ac`，最后由第四条规则将 `ab ac` 合成 `abac`。所以 `abaca` 的 Token 序列为 `[abac, a]`，ID 为 `[6, 0]`；把对应 Token 拼接即可还原原文。合并顺序不能丢：如果只存最终词表，不知道何时应执行哪条合并，就不能保证新的输入得到与训练规则一致的切分。

字符级 Tokenizer 与教学 BPE 会把训练时未出现的字符报告为错误。这个限制将在下一节消除：ByteLevel BPE 将 UTF-8 文本表示成固定的 256 种字节符号，再学习常见字节片段的合并。
