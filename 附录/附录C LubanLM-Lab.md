# 附录 C：LubanLM-Lab

主线已经固定模型结构，这一附录把几个部件暂时换掉，观察参数、显存、速度和短样本损失怎样变化。实验变体只在实验程序中创建，不写回正式 Base/Chat，也不保证仍可严格映射到 Qwen3 或 RKLLM。

先运行：

```powershell
. .\scripts\environment.ps1
python -m benchmark.lab
```

实现见 [lab.py](../benchmark/lab.py)。每个设置用固定种子，读取同一小段真实训练侧文本，做 10 次更新。前两步作为启动观察，后八步用于估算速度。这个重复小样本适合检查计算成本与能否学习，不适合排列一般语言质量。实验最多占用 20 分钟，实际完成设置写入 `lab_results.json`。

**MHA 与 GQA。** 基线有 8 个 Query 头、2 个 KV 头；MHA 变体把 KV 头也改为 8。输入、隐藏维度、层数和每头维度保留，所以 K/V 投影参数与缓存成本会增大。比较记录里的参数量和显存，再结合第 8.3 节的缓存公式解释，而不是只比较一个 loss。

**有无 QK-Norm。** 变体将 Q/K 的 RMSNorm 替换为恒等映射，观察归一化参数减少后分数与训练变化。移除归一化不改变输出张量形状，但会改变点积的尺度分布。短样本可以检验数值是否有限，不能由十步训练判断所有长训练是否稳定。

**LayerNorm 与 RMSNorm。** LayerNorm 先减均值再除标准差，RMSNorm 直接按均方根缩放。实验把 Block、最终层和 Q/K 的归一化一起替换，LayerNorm 不加 bias，因此这是一组明确定义的整体替换。若只想研究 Block 内的差别，需要另做只改 Block 的设置，不能把本次结果混写。

**GELU 与 SwiGLU。** 基线前馈有 gate、up、down 三个矩阵；GELU 变体用两矩阵前馈。保持相同中间宽度时，参数量并不相同，而且替换模块的初始化也会变化。因此这次实验主要展示结构与成本，不是同参数预算的公平质量比较。以后要比较质量，应先匹配参数量、训练量和验证集。

**不同词表。** 16k、32k、40k 分别使用实际训练出来的 Tokenizer，重新编码同一段文字。不能只改 `vocab_size` 后仍喂 32k ID；有的 ID 会越界，即使没越界也对应另一组片段。不同词表的每个预测单位不同，直接比较 token-level loss 或 tokens/s 无法得到文本质量排名。

**不同深度与宽度。** 基线隐藏宽度 512、11 层；另一组用 256、22 层，再一组用 768、6 层。头数和中间维度随宽度调整，保持 `H=n_q×d` 与 GQA 可整除关系。它们的参数总量不同，报告同时列参数量、速度和显存，不能称为“完全同规模深浅对比”。

**不同上下文长度。** 基线读取 64 个输入位置，再测 128 和 256。手写注意力的分数矩阵随长度近似平方增长，输出 logits 随长度线性增长。短序列每步快，并不一定表示每秒处理 Token 更多；长序列更费显存，也不代表模型已经掌握长文依赖。这里改变的是实验读取长度，配置容量仍然是 2048。

结果表见 [实跑报告](../docs/Windows实跑报告.md)。每一行都保留其变更因素和限制，正常训练与实验变体分开保存。FlashAttention、`torch.compile`、更多量化或更大评测都可以另开实验，当前主线不因为它们尚未实现而中断。
