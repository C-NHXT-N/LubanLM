# 6.1 正式启动 LubanLM

> 2026-10-16 路线更新：50M 已完成 5B Token 预训练及一轮 SFT，作为从零训练的教学案例保留；现有结果未证明可靠通用问答能力。第7章起转向成熟模型 LoRA 微调与部署，扩容另作可选实验。当前状态见 [项目状态](../PROJECT_STATUS.md)。

> 实验入口：先完成[低成本必修实验](../docs/低成本必修实验.md)。本节大规模数据与50M命令用于历史研究，需要对应的旧数据版本；目录采用workspace_env.ps1设置，使用已激活的原生环境，不是成熟模型LoRA入口。

现在已经有同一套 Tokenizer、模型、磁盘语料和训练循环。先把它们的关系确认一次：词表把文字变成 ID，模型配置决定每个 ID 查到多宽的向量，数据分片提供连续窗口，训练循环将窗口错开一位后计算损失。任意一处换了词表，其他文件都必须同步检查。

本次选择 50M 学习路径。`configs/config_50m.json` 是依据实际 Tokenizer 生成的运行配置；C2 中的候选配置仍保留，方便读者复算当时的参数设计。运行配置明确写入 PAD、BOS、EOS 的 ID，而不是假定任何外部词表都把它们编号为 0、1、2。

在项目根目录运行：

```powershell
. .\scripts\workspace_env.ps1
python -m training.train --config .\configs\config_50m.json --stage pretrain --tokens 8000000 --minutes 130 --length 256 --micro-batch 2 --accumulation 4 --lr 3e-4 --output $env:LUBAN_RUNS\checkpoints\50m-base
```

每个微批次处理 2 条长度 256 的输入，累积 4 次后更新，所以一次更新通常处理 `2×256×4=2048` 个输入位置。800 万是目标上限，更新步数向上取整后会略超过目标；若时间先到，就在更少 Token 处停止。报告写实际 `input_tokens`，不用命令行目标代替实测值。

程序先算一次固定验证 loss，保存 `initial.pt`，再开始学习。初始点的权重来自随机初始化，可以用于后面比较生成变化。训练过程的 loss 会波动，因为每次读取的文章段落不同；不能要求每一步都比前一步低。更有用的观察是较长区间的变化，以及独立验证样本上的损失是否改善。

日志中的 `peak_allocated_mib` 是 PyTorch 活跃张量曾达到的峰值，`peak_reserved_mib` 是缓存分配器曾保留的峰值。`nvidia-smi` 看到的设备总占用还会包含桌面程序、驱动上下文和其他进程，这些数字没有必要完全相等。估计安全余量时应同时看模型日志和设备状态。

历史0.5B使用同一模型结构与训练循环，但只做短基准，现已退出必修训练路线。它没有一个已经充分预训练的 Base 权重。以后要真正训练 0.5B，可使用其运行配置、梯度检查点和已验证的微批次组合重新制定预算；不能把本次随机输入基准继续命名为正式语料训练。

运行参数保存进 `run_config.json`，环境精确依赖见 [GPU 依赖锁定文件](../configs/requirements-gpu.lock.txt)，数据来源见 D 盘的 `sources.yaml`。本机运行事实集中在 [Windows 实跑报告](../docs/Windows实跑报告.md)。这几份记录共同解释“这个模型怎样得到”，只有一个权重文件无法表达这些条件。
