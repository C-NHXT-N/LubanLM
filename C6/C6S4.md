# 6.4 得到 LubanLM Base Model

> 2026-10-16 路线更新：50M 已完成 5B Token 预训练及一轮 SFT，作为从零训练的教学案例保留；现有结果未证明可靠通用问答能力。第7章起转向成熟模型 LoRA 微调与部署，扩容另作可选实验。当前状态见 [项目状态](../PROJECT_STATUS.md)。

> 实验入口：先完成[低成本必修实验](../docs/低成本必修实验.md)。本节大规模数据与50M命令用于历史研究，需要对应的旧数据版本；目录采用workspace_env.ps1设置，使用已激活的原生环境，不是成熟模型LoRA入口。

训练结束后，`last.pt` 保存最终模型与训练状态。它已经从随机参数在普通文章上进行了更新，所以可以作为这次教学实验的 Base 模型。Base 的含义是预训练阶段的模型版本，不代表它已经擅长聊天或达到了某个能力门槛。

训练检查点适合继续更新，却包含优化器与随机状态，文件通常比单纯权重大。为了理解标准模型目录，下面保留原生50M的历史导出示例；此步骤不是成熟模型部署的必需输入：

```powershell
. .\scripts\workspace_env.ps1
python -m export.prepare --checkpoint $env:LUBAN_RUNS\checkpoints\50m-base\last.pt --output $env:LUBAN_RUNS\exports\LubanLM-50M-Base
```

程序复用第 3.4 节的严格映射，把这次训练所得的同名参数载入标准 Qwen3 模型类，再保存 `config.json`、`model.safetensors` 和 Tokenizer 文件。架构参考 Qwen3 Dense，并不意味着使用了 Qwen 的预训练权重；本模型仍从随机初始化开始学习。

映射要求所有名称和形状匹配，不能忽略漏掉的参数。程序还比较同一输入的 logits，随后从导出目录重新加载再比较一次。数值差异只有落在设定容差内，才将本地导出与重新加载记为通过。这样能检查“文件确实被保存并读回”，而不是仅检查目录里出现了一个 `.safetensors`。

`lubanlm_conversion_manifest.json` 记录来源检查点、训练步数、处理 Token 数、模型配置和映射误差。`reload_verification.json` 保存重新加载的比较结果。原训练检查点仍留在 `checkpoints` 目录，标准推理目录另放在 `exports`，避免把优化器状态和交付权重混淆。

原生推理也可以读取这个标准目录：

```powershell
python -m inference.chat --checkpoint $env:LUBAN_RUNS\exports\LubanLM-50M-Base --question "Linux是什么" --temperature 0
```

这里使用50M历史提问模板，适合与其旧SFT权重对照；它与第7章成熟模型的原生模板不同。Base 没有按这种问答形式训练过，输出可能继续原文、偏离问题或不结束；不能把 CLI 能打印文字当成聊天训练已经完成。

当前交付是 **LubanLM-50M-Base 的教学版本**。实际训练规模、损失和样例见 [实跑报告](../docs/Windows实跑报告.md)。0.5B 只有短训练性能基准，没有正式 Base 发布物；本地标准目录也还没有经过 RKLLM 转换或 RK3576 运行验证。

预训练让参数更适合预测当前文本分布中的后续内容。它是否形成正确知识，需要具体评价。50M的历史SFT在同一Base上学习回答形式，相关入口保留在历史对照；第7章改为从成熟指令模型开始LoRA任务适配，不再将本节Base作为后期必修输入。

## Base 阶段的检查与后续门槛

Base应先用普通文章续写和独立验证集检查语言学习，不能只套聊天模板判断。当前5B预训练阶段已经结束，保留重复与错误作为分析材料；不再要求继续训练50M到可靠聊天才能进入下一章。感兴趣的学习者可选择继承扩容实验，应用路线则使用另一组成熟模型权重并建立自己的基线。

> 历史聊天评测保留在 [50M 历史对照](../docs/50M-SFT历史对照.md)；训练阶段已结束，能力评价不因课程推进而自动通过。
