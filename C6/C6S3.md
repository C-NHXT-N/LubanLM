# 6.3 简单评价 Base Model

> 2026-10-16 路线更新：50M 已完成 5B Token 预训练及一轮 SFT，作为从零训练的教学案例保留；现有结果未证明可靠通用问答能力。第7章起转向成熟模型 LoRA 微调与部署，扩容另作可选实验。当前状态见 [项目状态](../PROJECT_STATUS.md)。

> 实验入口：先完成[低成本必修实验](../docs/低成本必修实验.md)。本节大规模数据与50M命令用于历史研究，需要对应的旧数据版本；目录采用workspace_env.ps1设置，使用已激活的原生环境，不是成熟模型LoRA入口。

面对一段新文章，Base 模型要预测每个后续 Token。训练 loss 反映它对已经用来更新参数的窗口的表现，验证 loss 则来自独立划分的文章。两者回答的问题相近，但数据来源不同，所以不能只把训练 loss 下降作为完成训练的唯一证据。

本课程验证读取固定种子的窗口，不更新参数，也不使用 dropout。每个位置先算交叉熵，再按监督 Token 数加权汇总。固定窗口减少不同验证调用之间的抽样变化，但它仍只是验证集的一小部分；报告应该同时保留验证批次数，不能把它写成全部语料的精确困惑度。

困惑度（perplexity）是平均交叉熵的指数：

$$
\mathrm{PPL}=\exp(\overline{\ell})
$$

`平均损失` 是对当前评价文本各目标位置求平均得到的数，`exp` 是指数函数。例如损失 2 对应的 PPL 约为 7.39。这个变换让数值更直观，但没有额外引入另一套证据。不同 Tokenizer 切分了不同预测单位，PPL 通常不能跨词表直接比较。

在训练 loss 继续下降而验证 loss 长期上升时，应检查过拟合、训练/验证来源差异和数据处理是否一致。训练曲线突然跳变还可能来自更难的批次、恢复状态错误或学习率设置。短期波动与持续趋势要分开看。

接着体验一次标准评价工具：[lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness)。本课程通过原生模型适配器调用手写 `LubanLM`，不需要下载其他模型，也不使用 `model.generate` 代替核心计算。适配器的主要任务是接收题目和候选答案，返回每个答案的条件对数概率。

例如题目有 A、B、C、D 四个候选，工具分别询问“接在当前题目后生成 A 的概率”“生成 B 的概率”等，再把最高分选项和标准答案比较。它不是让模型写一篇回答后再由人凭印象打分。实际任务模板、题目划分与正确答案由工具定义。

本次采用 [C-Eval 验证数据](https://huggingface.co/datasets/ceval/ceval-exam)，计算机网络和操作系统各取 10 题、零样本设置：

```powershell
. .\scripts\workspace_env.ps1
python -m eval.lm_harness --checkpoint $env:LUBAN_RUNS\checkpoints\50m-base\last.pt
```

实现见 [lm_harness.py](../eval/lm_harness.py)。输出保存题目级记录、两个任务的准确率、样本数量、版本及适配器评分轨迹。数据卡列出 CC-BY-NC-SA 4.0，复用时保留来源和使用条件。本次不向外部测试服务器提交结果。

20 题的结果主要帮助理解工具流程。每个子任务多答对一题就改变 10 个百分点，随机猜测和小样本波动影响很大，不能据此排列模型优劣。尤其是短训练 50M，未必能可靠理解这些专业试题。准确率低也要原样报告，不能以“演示”为由换题或隐藏错误。

最终评价包由三部分组成：固定验证损失、固定续写样例、20 题工具体验。它们分别观察预测、生成和选择题行为，各自有适用范围。下一节保存真正训练后的权重，让这些结果能够对应到一个明确的 Base 模型版本。
