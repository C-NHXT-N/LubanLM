# 3.2 拼出完整 LubanLM

从教程目录执行；CPU例子沿用3.1节的 `$readerPython`，转换例子使用单独的 `$qwenPython` 环境。

Windows 完整训练补上了 padding、梯度检查点与 KV cache。原教学程序路径保留为兼容入口，核心实现见 [model/luban_lm.py](../model/luban_lm.py)；默认无缓存前向与本节讲解保持一致。

上一节的 Block 已能把 `[B,T,H]` 特征变成同形状的新特征。现在接上两端：输入端把整数 Token ID 查成向量，输出端把向量变成整个词表的分数。中间重复使用同一类 Block，就得到完整 LubanLM。

先沿用 C1 的六项手工词表与 C2 的微型形状：输入前五个 ID `[0,1,2,3,4]`，词表有 `V_vocab=6` 个条目，每个位置有 `H=4` 个特征。只有一条序列，所以模型接收 `[1,5]`，Embedding 查表后成为 `[1,5,4]`；Block 保持这个形状；最后每个位置要给六个 Token 各打一个分，输出成为 `[1,5,6]`。

一般流程就是：

```text
input_ids [B,T]
      ↓ Embedding：按整数 ID 查行
hidden_states [B,T,H]
      ↓ LubanBlock，重复 L 次
hidden_states [B,T,H]
      ↓ Final RMSNorm
hidden_states [B,T,H]
      ↓ LM Head：H → V_vocab
logits [B,T,V_vocab]
```

这里 B 是序列条数，T 是每条序列的 Token 数，H 是每个位置的特征数，`V_vocab` 是实际词表大小。Embedding 是 `[V_vocab,H]` 的可训练表，ID 必须在 `0` 到 `V_vocab−1` 之间；数字大小没有词义顺序，还必须使用与模型配套的 Tokenizer 映射。重复的 Block 逐层结合前文、加工特征，末尾再额外做一次 Final RMSNorm。它不属于最后一个 Block 内部的两个 Norm，不能漏掉。

LM Head（语言模型输出头）把最后的 H 个特征投影为 `V_vocab` 个分数。这些分数称为 logits，可以为负，也不要求总和为 1。只有沿词表这一维做 Softmax，才得到概率；选哪个 Token、如何连续生成，留到第 8 章。本节先检查每个位置能否产生正确数量的分数。

完整程序是 [luban_lm.py](program/3.2/luban_lm.py)。配置类 `LubanConfig` 读取 C2 的 JSON；`LubanBackbone` 保存输入表、Block 列表和最终 Norm；`LubanLM` 再增加输出头。主干中连接模块的代码可以概括为：

```python
# LubanBackbone.forward 内的执行顺序，变量来自完整模型。
hidden_states = self.embed_tokens(input_ids)
for layer in self.layers:
    hidden_states = layer(hidden_states)
return self.norm(hidden_states)
```

Block 列表使用 `nn.ModuleList` 登记，让 PyTorch 能找到每一层的参数。`LubanLM.forward` 再将返回的隐藏向量交给 `self.lm_head`。这些名称划分的是代码职责，数据仍沿上面的同一条路线流动。

在 LubanLM 根目录，用 [C3.1](C3S1.md) 准备好的 Miniconda 解释器启动 Python，可以调用一个微型完整模型：

```powershell
& $readerPython
```

```python
from dataclasses import replace
from pathlib import Path
import sys
import torch

root = Path.cwd()
sys.path.insert(0, str(root / "C3" / "program" / "3.2"))
from luban_lm import LubanConfig, LubanLM

base = LubanConfig.from_json(root / "C2" / "program" / "2.4" / "config_50m.json")
# 只缩小教学尺寸，模块顺序和计算方法不变。
config = replace(base, vocab_size=6, hidden_size=4, num_hidden_layers=2,
                 num_attention_heads=2, num_key_value_heads=1,
                 head_dim=2, intermediate_size=6, context_length=16)
model = LubanLM(config)
input_ids = torch.tensor([[0, 1, 2, 3, 4]], dtype=torch.long)
logits = model(input_ids)
print(input_ids.shape, logits.shape)  # [1,5] → [1,5,6]
```

`torch.long` 用来保存整数编号，Embedding 根据它查行。这里手工编号只演示接口，权重随机初始化，输出没有语言能力上的含义。目录 `3.2` 以数字开头，不能写成常规点分包名；将该目录加入 `sys.path` 后即可导入 `luban_lm`，而它会自行加入 `3.1` 的组件路径。

实际训练时，输入应来自 C1 最终选定的 Tokenizer，不能沿用这六个手工条目。模型词表大小和 PAD、BOS、EOS 的 ID 都要与 Tokenizer 对齐。当前 C2 JSON 尚未确定最终特殊 ID；`LubanConfig` 提供了对应字段，C3.4 的目录准备程序会读取真实值。模型前向不会自动补 BOS/EOS，是否添加由样本格式决定。

现在换回 50M 候选，退出交互式 Python，在根目录 PowerShell 中执行：

```powershell
& $readerPython C3\program\3.2\luban_lm.py
```

脚本默认读取 50M JSON、固定随机种子，在 CPU 上创建 8 个随机 ID 并执行一次前向传播。按配置推导，应打印输入 `(1,8)`、输出 `(1,8,32000)`、参数量 49,558,400。这里输出的 32,000 来自候选词表，不能与刚才微型演示的六个条目混在一起。

只改变批量与长度，可以观察两条外部轴：

```powershell
& $readerPython C3\program\3.2\luban_lm.py --batch-size 2 --sequence-length 5
```

此时输入为 `[2,5]`，查表和 Block 中间表示为 `[2,5,512]`，输出为 `[2,5,32000]`。B、T 来自运行输入，H、`V_vocab` 来自模型配置。指定另一份配置时仍使用同一个模型类：

```powershell
& $readerPython C3\program\3.2\luban_lm.py --config C2\program\2.4\config_0.5b.json --sequence-length 4
```

对应输出为 `[1,4,32000]`，参数量应为 488,964,864。0.5B 仅以 float32 保存权重就约需 1.82 GiB，实例化时还可能产生额外分配，不能为看一个形状忽略主存开销。首次练习优先使用微型或 50M；下一节统计大模型参数时会使用只保存形状的方式。

C2 的两个候选共享 Embedding 与 LM Head 权重。输入时用 ID 查出 E 的一行，输出时将隐藏向量与 E 的每一行分别做点积，得到对应 Token 的分数。E 的形状为 `[V_vocab,H]`，h 是最终归一化后的单个隐藏向量：

$$
\operatorname{logits}_{b,t,:}=h_{b,t,:}E^\mathsf{T}.
$$

b、t 选择某条序列、某个位置，冒号表示取这一位置的全部词表分数。E 的转置形状为 `[H,V_vocab]`，因此乘法恰好从 H 维得到 `V_vocab` 维。代码用一行实现真正共享：

```python
self.lm_head.weight = self.model.embed_tokens.weight
```

两处指向同一个 `Parameter`，更新时共同变化；`model.parameters()` 默认也只统计一次。因此共享输出头不增加第二份 `V_vocab×H` 参数，但依然要完成输出投影的乘法。

当前模型只构造因果遮罩，没有接收单独的 PAD 遮罩。示例中输入等长且没有填充，计算可以直接进行。如果把短序列补到统一长度，因果遮罩只检查位置先后，不能识别哪些 Key 是 PAD；需要额外禁止读取填充位置，并在 Loss 中忽略填充目标。另一种办法是将文本整理成没有 PAD 的等长片段，数据章节再决定具体格式。

现在模型接口已确定：接收 `[B,T]` 的整数 ID，返回 `[B,T,V_vocab]` 的分数。下一节将改变输入、核对参数和中间形状，并检查这些分数能否用于计算 Loss、反向传播和少量样本学习。
