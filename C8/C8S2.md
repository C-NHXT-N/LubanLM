# 8.2 Sampling

模型、环境与目录见[教材基准](../docs/教材基准.md)；历史任务结果见[教学案例](../docs/cases/2B任务适配分析.md)，当前数据状态以[项目状态](../PROJECT_STATUS.md)为准。

上一节总选最大分数。现在仍用 `[2,0,-1]`，但希望按概率抽取候选，让一个模型产生不同回答。抽样只改变“怎样选”，不更新模型参数，也没有增加任何新知识。

温度（temperature）先将分数除以一个正数再做 softmax：

$$
p_j=\frac{\exp(z_j/\tau)}{\sum_k\exp(z_k/\tau)}
$$

`z_j` 是第 `j` 个候选的原分数，`τ` 是温度。小于 1 会把候选差距放大，使高分项更集中；大于 1 让分布更平缓。原生50M教学采样函数约定温度0使用greedy，直接取最大值，不执行除以零。温度更高可能增加变化，也可能增加不连贯内容。

Top-k 先只保留分数最高的 `k` 个候选。例如三候选取 `k=2`，ID 2 被排除，剩余两项重新归一化。它限制候选数量，但不管两个候选之间的概率差距多大。

Top-p 又叫累计概率采样，先把候选按概率从高到低排序，保留累计概率达到阈值 `p` 的最小前缀。原概率 `[0.8438,0.1142,0.0420]` 在 `p=0.9` 时保留前两项，因为第一项还未达到 0.9，加上第二项后约为 0.958。程序保留跨过阈值的那一项，至少保留一个候选；把它也删掉会错误缩小候选集合。

以下独立算例可以直接运行：

```python
import torch
from inference.generate import sample

logits = torch.tensor([2.0, 0.0, -1.0])
generator = torch.Generator().manual_seed(2026)
print(sample(logits, [], temperature=0.0))
print(sample(logits, [], temperature=1.0, top_k=1, generator=generator))
print(sample(logits, [], temperature=1.0, top_p=0.9, generator=generator))
```

前两行都只能选 ID 0，第三行允许在保留候选中抽样。固定种子帮助复现这一串抽样，连续调用仍会推进生成器状态；把每一步都重新设成同一随机种子，会变成另一个算法。

重复惩罚（repetition penalty）降低已经出现过的 ID 的分数。若分数为正，除以大于 1 的惩罚值；若分数为负，乘以该值，让它更负。不能对正负数都简单除以惩罚值，否则负分会变得更高，反而奖励重复。原生50M采样器检查提示与已生成内容中出现过的ID，并对每个不同 ID 处理一次。

原生50M历史交互设置为温度0.7、Top-k 40、Top-p 0.9、重复惩罚1.1；这些不是成熟模型的既定默认值。旧 `eval.observe` 仅记录原生模型。成熟模型从其生成配置与上游建议起步，再固定参数做任务对照，本轮没有新的采样实测。看结果时区分“同一意思换了表达”与“增加了错误内容”，不能把更随机直接理解为更聪明。

EOS 不应被 Top-k 或 Top-p 逻辑强制保留，也不应被永久禁止；它和其他可生成候选一起按当前分数筛选，选中时结束。若模型一直不选 EOS，最大新 Token 数仍提供明确停止边界。下一节处理重复前向所浪费的计算。


上述三候选与 `sample()` 是独立原理实验，不加载50M权重。成熟模型主线应另核查生成配置、特殊Token、重复惩罚的作用范围与停止规则，不能把旧采样函数当作已经适配的Qwen生成接口。
