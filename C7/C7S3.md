# 7.3 LoRA 任务微调

本节遵循[教材基准](../docs/教材基准.md)。原模型短测、历史任务实验与当前数据状态分别判断。

输入样本和标签固定后，下一步决定更新哪些参数。50M历史实验更新了整个模型，而成熟模型主线采用LoRA：保留原权重，在选定线性层旁边加入可训练的低秩增量。

## 先让一个输出学会改变

暂时离开语言模型，用一个可手算的线性层。输入列向量 `x=[1,2,1]ᵀ`，冻结权重为：

```text
W = [[1,0,0],       A = [[1,0,1]],      B = [[0],
     [0,1,0]]                               [0]]
```

W的两行各与输入相乘再求和，因此 `Wx=[1,2]ᵀ`。我们希望得到目标 `[3,0]ᵀ`，即补上 `[2,-2]ᵀ`。先用A把三个输入压成一个数：`Ax=1×1+0×2+1×1=2`；再用B把这个数映射回两个输出。B初始为零，所以 `BAx=[0,0]ᵀ`，新分支还没有改变原输出。

将本例缩放系数设为1，预测为 `y=Wx+BAx`。用平方误差 `loss=½[(y₁−3)²+(y₂−0)²]`，初始loss为4。对B的两个元素，梯度分别为 `(1−3)×2=−4` 与 `(2−0)×2=4`。梯度下降沿梯度的反方向修改参数；学习率0.25时，B从 `[0,0]ᵀ` 变为 `[1,−1]ᵀ`。这时补偿为 `[2,−2]ᵀ`，输出恰好成为 `[3,0]ᵀ`。

下面是完整CPU算例，只依赖PyTorch；可以在[必修实验](../docs/低成本必修实验.md)环境中执行：

```python
import torch

W = torch.tensor([[1., 0., 0.], [0., 1., 0.]])  # 不参与梯度更新
A = torch.nn.Parameter(torch.tensor([[1., 0., 1.]]))
B = torch.nn.Parameter(torch.zeros(2, 1))
x = torch.tensor([[1.], [2.], [1.]])
target = torch.tensor([[3.], [0.]])
optimizer = torch.optim.SGD([A, B], lr=0.25)
y = W @ x + B @ A @ x
loss = ((y - target) ** 2).sum() / 2
loss.backward()
print("before", y.detach().flatten().tolist(), float(loss.detach()))
print("grad A/B", A.grad.tolist(), B.grad.tolist())
optimizer.step()
print("after", (W @ x + B @ A @ x).detach().flatten().tolist())
print("W", W.tolist())
```

输出为更新前 `[1,2]`、loss 4，A的梯度全零、B的梯度 `[[-4],[4]]`，更新后 `[3,0]`，W保持不变。A同样是可训练参数，但第一步B为零，误差无法通过它传到A；B变成非零后，后续非零误差才可能同时更新A。这也解释了常见的A随机初始化、B零初始化：开始保持基座输出，又能让梯度启动。若A、B同时为零，两者梯度都无法启动。

这个例子人为挑选了输入、目标和学习率，单样本一步拟合不代表语言模型一步学会任务。真实语言模型用第5章的交叉熵衡量回答Token预测误差，由所有后续层反向计算A/B梯度；LoRA没有替换训练目标。

## 对应到真实线性层

若原线性变换为 `y=Wx`，设 `W` 的形状为 `[d_out,d_in]`，LoRA用两个较小矩阵表示增量：

$$
y=Wx+\frac{\alpha}{r}BAx
$$

`A` 的形状为 `[r,d_in]`，`B` 为 `[d_out,r]`，所以 `BA` 与 `W` 同形。`r` 是低秩维度，`α` 控制增量尺度。新增可训练元素为 `r(d_in+d_out)`，比 `d_out×d_in` 少时，可以显著减少梯度和优化器状态；原模型权重与激活仍需占用显存，LoRA不保证任意序列都装得下16GB显卡。

刚才的r=1、α=1，训练5个数、冻结6个数；若一个4096×4096层取r=16，则训练131,072个数，而原层有16,777,216个数。后者是尺寸算例，不是Qwen每一层的实际形状。r限制增量可变化的方向数，并不代表任务知识的条数。

专用实现复用Transformers与PEFT，从真实模块名称确认语言解码器目标层，排除视觉、嵌入与输出头。实际列出186个目标模块，可训练参数16,819,200个，完整名称保存在运行配置。本轮固定rank16、alpha32、dropout0.05与BF16，不将这些参数称为最优配置。

先用少量训练侧样本检查标签、有限损失、梯度和一次更新，再估算可用的序列长度、微批次与梯度累积。显存不足时先核查精度、激活与序列长度。4位LoRA加载属于另一个需验证的训练方案，不能因板端使用W4A16，就把GPU训练也自动写成4位。

训练按助手监督Token计算损失，保留回答首Token及正确的结束标记。epoch、输入Token、监督Token、更新步数和墙钟时间分别记录。训练loss下降可能伴随任务记忆和通用能力退化，开发集检查应覆盖第7.1节固定的通用问题。

每次实验使用独立运行目录，保存适配器、训练配置、数据版本和可恢复状态。首次任务微调从原模型初始化；恢复同一次训练才读取对应优化器与计数，不能将不同候选模型的适配器当作可交换权重。基座原文件保持只读。

现有 [training/train.py](../training/train.py) 是LubanLM原生50M/0.5B训练器，不支持直接加载成熟Qwen权重与LoRA。成熟模型已新增 [专用训练入口](../scripts/linux_assistant/train.py)，支持最小更新与恢复检查、正式训练和独立检查点。首轮参数、前置检查及真实完成状态见 [Linux助手实验](../docs/Linux助手微调与交付.md)；程序存在不等于训练或任务质量通过。

最小实验已实际用16条不同训练记录、微批次1和累积8完成4次更新。第2步保存并恢复372项优化器状态、步数、学习率与随机状态；冻结权重摘要未变，适配器更新后能够重新加载推理。这证明训练链路可以工作，不能证明任务已经学好。

历史534条训练记录上的2B实验完成134步，训练误差下降，最终任务开发题从11/120提高到28/120，仍低于80%门槛。哪些回答变好、哪些变短却仍有错误，见[逐条教学案例](../docs/cases/2B任务适配分析.md)。这是旧数据上的开发结果，封存验收未运行；不能作为现行统一数据集的成绩。早期两组125步方案保留在带日期的实验报告，不再作为本节默认配置。

现行统一数据集尚未获训练批准，默认入口会阻断。必修读者先完成上述矩阵更新与第7.2节真实标签检查，使用[小实验](../docs/低成本必修实验.md)体验保存和恢复；具备资源和批准数据后再运行正式任务LoRA。工程跑通、训练拟合改善和新题回答改善分别检查。
