# 10.4 构建、传输与故障定位

部署目录来自9.4的独立包。先确认文件摘要，再在板端创建项目虚拟环境、离线安装和编译：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install --no-index --find-links wheels --require-hashes -r requirements.lock.txt
PATH="$PWD/.venv/bin:$PATH" sh build.sh
.venv/bin/python frontend.py --root . --verify-only
```

[build.sh](../deploy/linux_assistant/build.sh)先核对部署清单，再使用包内头文件与运行库构建C++程序，保存编译结果摘要。前端启动前还检查实际可执行文件摘要，防止使用旧二进制。构建需要板端已有编译器和Python虚拟环境支持；缺失时记录环境问题，不自动改装系统。

## 根据失败阶段检查

| 阶段 | 首先保留的证据 |
|---|---|
| 传输或摘要不符 | 文件名、预期/实际SHA、`.part`长度与前缀摘要 |
| 构建失败 | 编译器版本、完整诊断、头文件和ARM64运行库来源 |
| 动态库加载失败 | 可信程序的ldd结果、实际搜索路径和ABI/版本 |
| 模型初始化失败 | model路径、模型SHA、Runtime/驱动及返回码 |
| 输出乱码或异常停止 | 请求编号、输入ID、原生EOS、流式字节、runtime.log |
| 多轮串话 | 完整保留历史、裁剪结果和清理缓存返回码 |

不能把Windows或Linux x86_64运行库当成ARM64运行库。不要看到 `undefined symbol` 就替换系统库；先确认实际加载了哪一份库。原有50M、Qwen权重和量化文件均保留，修复也使用独立实验目录。
