# 10.2 用C/C++加载与运行合并模型

第9章得到的是 `.rkllm` 文件；它不是可执行程序。板端应用先让Runtime创建模型句柄，再把已经套好模板的Token送进去，接收回调，最后释放句柄。本节先做一次请求，再解释持久聊天程序增加了什么。

## 一次请求的完整生命周期

最小完整源码是[single_request.cpp](program/single_request.cpp)，只依赖Runtime1.3.1头文件与ARM64运行库。输入为模型路径和 `native-tokens.tsv`，程序读取第一行的 `问题编号<TAB>空格分隔ID`；这些ID必须由同一版模型Tokenizer在PC产生，不能把汉字的Unicode编号直接提交给NPU。

先观察源码中相连的五步。`rkllm_createDefaultParam()`提供默认参数，再明确模型路径、2048上下文与256输出上限。`rkllm_init(&handle,&p,&cb)`加载文件并准备内存，成功后handle代表这次模型实例。接着 `input_type=RKLLM_INPUT_TOKEN` 使Runtime读取 `ids.data()`，长度为 `ids.size()`；`rkllm_run`执行同步推理，运行期间数组和回调状态必须保持有效。结束后 `rkllm_destroy(handle)`释放实例，运行出错也仍释放。

回调中的NORMAL表示收到一个片段，ERROR记录失败，FINISH记录运行结束。中文一个字符可能跨回调，最小程序先拼接全部字节，再一次输出完整文本。回调返回0表示继续，不能把一次NORMAL当成整句完成。FINISH也不保证模型自然选中了助手EOS；达到长度上限同样可能完成一次运行。最小程序用于观察生命周期，正式程序另有原生停止ID、错误协议和计时。

在独立的板端实验目录准备以下文件：

```text
single_request.cpp     本节源码
include/rkllm.h        固定SDK 1.3.1的头文件
lib/librkllmrt.so      同SDK的Linux ARM64库
model.rkllm           第9章转换产物，或已验证的原模型导出
native-tokens.tsv     匹配原模型和原生模板的输入ID
```

原模型复现可从作者工作区 `exports/rk3576/Qwen3.5-2B/` 取模型与Token文件，源码和SDK来源见[实测入口](../docs/Qwen双模型RK3576实测.md)。新下载教程不附带这几个GB的文件；应先完成第9章原模型转换与Token准备。没有板卡的必修读者直接阅读下面的历史原始记录，不需要先取得未发布的任务模型。

板端Linux编译运行命令如下（本次交叉编译因工具链临时文件权限等错误失败，尚未确认构建或上板运行此新教学程序）：

```sh
g++ -O2 -std=c++17 -Wall -Wextra -Iinclude single_request.cpp \
  -Llib -lrkllmrt -Wl,-rpath,'$ORIGIN/lib' -o single_request
./single_request model.rkllm native-tokens.tsv
```

已有原模型短测在约8GB的LubanCat-3上完成；2B当时进程峰值约1.45GiB，4B约2.55GiB，仅供准备预算，不是这份新程序的实测。模型加载和短问答预留数分钟，转换时间另计。缺头文件先查SDK目录，找不到动态库先查ARM64架构和搜索路径，初始化失败再核对模型摘要、Runtime与驱动；不要通过替换系统库试错。

## 一次实际运行留下什么

历史[原模型测试器](../scripts/rk3576_probe.cpp)采用相同的加载、输入、回调和释放接口，记录了下面这次实际运行：Qwen3.5-2B、round=1、问题intro、返回码0、finished=true，输出全文为：

```text
我是通义千问，一个基于通义大模型构建的 AI 助手。我擅长处理文本、代码、逻辑推理及创意写作。如果您有任何问题或需要帮助，请随时告诉我！
```

该条总时间8.49329秒，首回调0.848419秒，Runtime generate为42 Token/7642.17毫秒。数据来自[随书记录](../docs/cases/board-intro.json)，属于2026-10-18原模型测试器的实际输出，不是本节新程序或任务LoRA的成绩。模型自述只是生成文本，不能验证它自称的身份、能力和版本；第11章继续从这条记录计算速度。

## 从单次运行到持续聊天

[board_chat.cpp](../deploy/linux_assistant/board_chat.cpp)使用固定Runtime1.3.1头文件中的接口，启动时加载模型一次，退出时销毁句柄。输入为请求编号和完整Token ID，输出为JSON行；SDK诊断和普通日志写到stderr，避免混入结果通道。

## 每次请求的顺序

1. 检查编号、Token范围与输入长度。
2. 调用 `rkllm_clear_kv_cache` 清理上次运行状态。
3. 用 `RKLLM_INPUT_TOKEN` 提交已完成模板处理的Token，`keep_history=0`。
4. 回调持续回传文本字节和计时；模型原生结束ID、Runtime完成、长度上限、中断和错误分别记录。
5. 中断或原生结束触发暂停时处理剩余运行状态，避免污染下个请求。

输入上限1792 Token、输出上限256，总上下文2048。greedy参数固定，关闭思考模式。不重复设置模板，也不让Runtime额外管理一份会话历史。

C++接收流式UTF-8字节后编码成十六进制JSON字段，Python用增量解码器还原中文；这可处理单个汉字跨两次回调的情况。结束Token不计作可见输出速度样本。

本轮源码已通过ARM64交叉编译、与匹配运行库链接，以及宿主协议替身测试。替身只验证结果通道、结束和错误分支，不代表NPU执行。实际板端构建命令见10.4，质量与性能另验。
