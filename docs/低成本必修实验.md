# 从空目录到可恢复的小模型

本实验把第1—6章压缩为一条离线路线：用四句随代码提供的文字建立字符词表，随机初始化小模型，更新8步，保存，再恢复到累计16步，最后生成文字。它复用本书的[模型](../model/luban_lm.py)和[生成循环](../inference/generate.py)；训练入口是用于观察的[短循环](../training/reader_lab.py)，不依赖50M历史数据、权重或正式任务数据门禁。

小模型有2个Block、隐藏维度32、4个Query头与2个KV头，FP32、CPU、单样本、无梯度累积。字符词表同时收录观察文本的字符以避免未知字符；训练更新只读取TRAIN，DEV只用于观察损失，未拿它选择配置。这个小语料不适合评价一般语言能力。完整50M的5B训练属于历史案例，不需要重复支付该预算。

## 准备与第一次运行

解压教程，使目录为 `任意工作区/LubanLM/`，进入这个教程目录。准备Python3.11和PyTorch2.12.1、Tokenizers0.22.2、NumPy1.26.4。已有本书原生环境可直接使用；新电脑可在PowerShell新建专用环境（先安装Miniconda，不向base安装依赖）：

```powershell
conda create --prefix ..\.conda\reader-py311 python=3.11 pip -y
$readerPython = (Resolve-Path ..\.conda\reader-py311\python.exe).Path
& $readerPython -m pip install torch==2.12.1 tokenizers==0.22.2 numpy==1.26.4
. .\scripts\workspace_env.ps1
& $readerPython -c "import torch,tokenizers; print(torch.__version__,tokenizers.__version__)"
```

安装源按自己的网络选择；上述安装命令是待新电脑验证的安装说明，本次没有重新联网安装。PyTorch官方CPU包也可用于此实验。程序固定使用CPU，不占用显卡。首次导入可能较慢，建议预留2GB可用系统内存、100MB运行产物空间，依赖安装空间另计；这是保守准备预算，实测时间另见[复现记录](读者路线复现记录.md)。

从空结果目录开始运行，重复实验换一个新目录名：

```powershell
& $readerPython -B -X utf8 -m training.reader_lab --output ..\runs\reader-lab\part --stop-after 8
& $readerPython -B -X utf8 -m training.reader_lab --output ..\runs\reader-lab\resumed --resume ..\runs\reader-lab\part\last.pt --stop-after 16
```

`stop-after`指累计更新步数。第二条只新增8步。没有恢复时，入口固定随机种子、词表与初始化；恢复时同时还原模型、AdamW、采样器和随机状态。只载入自己生成且可信的 `last.pt`。程序拒绝覆盖非空结果目录，防止把两次实验写成同一份记录。

控制台每步打印 `step`、`train_loss`、`input_tokens` 与 `supervised_tokens`；第1步loss约3.83，不要求每步单调下降。运行后得到：

```text
../runs/reader-lab/part/
  tokenizer.json   本次字符到ID的映射
  initial.json     随机模型的观察损失与续写
  last.pt          第8步权重、优化器、采样器及随机状态
  result.json      第8步结果与逐步训练记录
../runs/reader-lab/resumed/
  tokenizer.json
  last.pt          累计第16步恢复状态
  result.json      累计16步记录，updates_this_run应为8
```

查看 `result.json` 中同一提示“Linux是”的输出。短训可能仍然重复某个字，这也是结果，不需要为了让它像聊天助手而反复追加训练。小实验交付的是可恢复流程、可追踪的预测目标与原始输出。第6.2节再比较50M不同阶段的真实结果。

## 检查恢复是否真的接上

在另一个空目录不间断运行16步：

```powershell
& $readerPython -B -X utf8 -m training.reader_lab --output ..\runs\reader-lab\continuous --stop-after 16
```

保持依赖和CPU环境一致，连续运行与恢复运行的第9—16步损失、最终权重、AdamW状态与生成ID应一致。可用 `& $readerPython -m scripts.verify_reader_route --output ..\reports\my-reader-route` 自动生成三次运行并逐项比较。跨PyTorch版本或不同后端不承诺逐位一致；只看生成文字相同也不足以证明恢复状态正确。本次实际对比结果见[复现记录](读者路线复现记录.md)。

| 失败现象 | 检查方法 |
|---|---|
| 找不到training或model | 当前目录应为LubanLM；重新加载workspace_env.ps1，检查PYTHONPATH包含教程目录 |
| 找不到torch或tokenizers | 用同一个 `$readerPython -m pip show torch tokenizers` 核对解释器，勿混用系统python |
| output must be empty | 选择新的结果目录；不删除历史结果来掩盖失败 |
| checkpoint/config/data mismatch | 恢复该入口自己的last.pt；保留对应源码、词表及依赖，不换模型或文本 |
| step没有到16 | stop-after是绝对步数；恢复路径须指向第8步文件 |
| 输出重复或loss起伏 | 检查loss有限、计数与文件齐全；16步不能证明语言能力合格 |

## 第6章怎样接到第7章

这里保存的 `last.pt` 只交给原生LubanLM加载器。第7章继续使用下一Token预测、标签掩码和梯度更新这些原理，但开始加载已有能力的成熟指令模型，以便把预算集中在任务适配。Qwen具有不同架构、词表与特殊ID，不能继承这个小模型或50M的Tokenizer与权重。

第7.2节先用CPU读取Qwen原生Tokenizer，运行[逐Token程序](../C7/program/inspect_chat_labels.py)，不加载2B权重；第7.3节手算一次LoRA更新。第8章对照相同的生成原理与不同模型接口；第9.3节量化算例也不需要NPU。第10—11章先沿真实原模型记录分析板端程序和计时，有对应硬件再做扩展复现。

正式Qwen任务训练需要16GB级显卡及经过批准的数据。现有历史实验约9GiB框架显存、约16分钟含开发生成，只代表短样本配置，不是1024长度或新数据的保证；当前活动数据尚未获准训练，不应绕过门禁。必修读者在这里完成工程小实验，再阅读失败案例；模型质量和板端交付各按自己的证据验收。
