# Qwen3.5-2B原模型开发基线

本流程只运行统一开发集：120道任务题和40道通用题。使用原模型BF16、同一系统提示、greedy、关闭思考、最多256个输出Token。验收集不会加载。每道题只发送最后用户问题之前的上下文与用户问题，最后的目标助手答案仅存作评分参考。

## 启动与续跑

从工作区执行：

```powershell
& C:\Lab\LubanLM-lab\LubanLM\scripts\linux_assistant\start_baseline.ps1
```

脚本使用独立训练环境的解释器启动隐藏后台进程，终端退出后进程继续运行。再次运行同一脚本时：已运行的任务不会重复启动；失败或中断的任务复用已验证完成的批次；已完成的任务直接显示报告位置。进程级文件锁防止同一任务并发写入。

在会清理子进程的工具宿主中使用 `start_baseline.ps1 -KeepAlive`，让启动会话保留到评测结束；Codex本次使用该方式，运行会话留在后台，无需轮询或人工守候。普通Windows终端可使用上面的默认分离启动方式。

配置：`LubanLM/configs/linux-assistant-qwen35-baseline.json`。

## 性能与正确性

程序一次分词，按输入长度组织批次并使用左填充，原生EOS逐行截断。先在8道覆盖不同类别和长度的开发题上测量批次1、2、4、8；比较完整greedy输出Token，只有与batch=1完全一致的批次才能入选。预热不计入批次耗时，选择通过校验且耗时最低的批次；若不一致，自动使用一致的较小批次。显存不足时降到已经通过校验的较小批次，并记录事件。

批处理会降低逐题解码的调度开销，但不会为了提高利用率改变最大输出长度、采样规则或题目。批次耗时明确标记为共享耗时，不冒充每题独立延迟。

## 自动保存的结果

输出目录：`C:/Lab/LubanLM-lab/reports/linux-assistant-baseline-qwen35-20261020/`。

| 文件 | 用途 |
|---|---|
| `status.json` | 当前阶段、已完成数、预计剩余时间；结束为completed，失败为failed并附错误 |
| `launch.json`及`worker-*.log` | 后台进程ID、启动参数、标准输出与错误日志 |
| `prompt-audit.json` | 去除目标答案的检查、输入长度与未加载验收集证明 |
| `autotune.json` | 批次耗时、显存、逐Token一致性结果与最终选择 |
| `identity.json` | 固定模型版本、数据摘要、生成设置和执行代码摘要 |
| `answers.jsonl` | 按题目原顺序保存的输入、原始答案、Token、停止原因和规则筛查 |
| `review-queue.jsonl` | 待逐题语义复核的结果 |
| `summary.json`及`REPORT.md` | 完成后的耗时、显存、规则筛查统计和报告 |

每个完成批次通过临时文件和原子替换提交，不需人工保存。中断重启时校验模型、题目、代码和设置摘要，并核对已保存问题的输入Token；条件变动会拒绝复用旧结果。规则筛查不等于语义评分，复核完成前不发布任务通过率。

旧统一数据开发结果曾把参考助手答案放入输入，现已撤回并保留证据，见 `reports/linux-assistant-evaluation-incident-20261020.json`。本次原模型基线完成后，适配器应通过相同修正入口重新评测后再比较。
