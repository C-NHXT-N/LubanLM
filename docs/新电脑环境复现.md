# 新电脑独立环境与实体网卡镜像下载

本页说明Windows RTX 5060 Ti上的环境准备入口。使用现有Miniconda创建工作区独立Python 3.11环境，不向base或系统Python安装项目依赖。验收以工作区 `reports/environment-setup-*/summary.json` 和 `validation.json` 为准；安装结束和模型质量验收是不同结论。

## 执行入口

在教程目录 `LubanLM/` 的PowerShell中运行：

```powershell
& .\scripts\bootstrap_environment.ps1 -Interface WLAN
```

脚本使用已有 `C:\Tools\miniconda3`，将独立环境放到工作区 `.conda/lubanlm-py311`，缓存放到 `.cache/`。已有正确的Python 3.11环境会复用；不匹配的环境或PyTorch版本会停止并说明，不自动删除或覆盖。若失败，先看对应日志，修正原因后重跑，经过校验的下载缓存可以复用。

当前固定GPU包为 `torch==2.12.1+cu130`，其余依赖来自项目GPU清单。安装后写出实际pip版本列表与Conda显式包清单；这些记录用于重建已测试环境，不把镜像中的“最新”作为永久前提。

本次首次验收发现PyArrow 26与项目固定的NumPy 1.26.4运行时不兼容，虽然 `pip check` 未报告冲突，导入Datasets仍失败。清单现固定旧环境已用的 `pyarrow==25.0.1`，并保留失败日志；环境验收必须包含实际模块导入，不能只看安装器退出码。

## 保持Clash启用的直连方法

底层复用 [direct_mirror.py](../scripts/direct_mirror.py)：只选择有默认网关的实体IPv4网卡，将socket绑定网卡索引和当前IPv4地址；通过同一实体连接查询独立HTTPS DNS，拒绝私网及FakeIP响应；HTTPS保留证书与域名校验。

Conda和pip使用临时回环安装转发器，转发器只允许已批准的镜像HTTPS主机，上游socket仍由实体绑定逻辑建立。它与Clash的本机端口、Meta网卡没有关联；只给安装子进程设置代理，不修改Windows代理、路由、Clash或TUN。脚本结束时关闭临时转发器。

| 内容 | 来源 |
|---|---|
| Python与Conda依赖 | 清华conda-forge镜像 |
| 普通Python包 | 清华PyPI镜像 |
| 固定Windows GPU PyTorch包 | 南京大学PyTorch镜像，校验固定SHA256 |
| 模型 | 小文件HF-Mirror；大文件ModelScope官方Qwen副本，实体直连并校验摘要 |
| 数据 | 后续使用国内镜像及实体网卡下载入口，尚未下载新数据 |

`HF_ENDPOINT` 只改变服务入口，不保证绕过TUN。因此后续模型和数据下载也必须使用实体网卡下载器，检查重定向主机与网络记录，不能直接把普通Hugging Face客户端下载视为已经满足实体直连。安装时禁止回退官方源或其他出口，无法访问时保留失败。

## 使用独立解释器

### 两个Qwen模型的下载与离线问答

2026-10-18已下载 `Qwen/Qwen3-4B-Instruct-2507` 与 `Qwen/Qwen3.5-2B`，保存在工作区 `models/Qwen/`。在本页安装入口已完成的当前电脑上，从教程目录运行以下现有脚本；下载可断点续传，完整文件会先校验。安装脚本复用此前缓存的固定PyTorch wheel，并创建独立Qwen环境，以保留50M环境的Transformers版本。

```powershell
$env:PYTHONPATH=(Get-Location).Path
$report=Join-Path (Resolve-Path ..).Path 'reports/qwen-comparison-20261018-032232'
& C:\Tools\miniconda3\python.exe -B -X utf8 -m scripts.prepare_qwen_models --interface WLAN --report $report
& C:\Tools\miniconda3\python.exe -B -X utf8 -m scripts.setup_qwen_environment --report $report
$env:HF_HUB_OFFLINE='1'
$env:HF_DATASETS_OFFLINE='1'
& ..\.conda\qwen-py311\python.exe -B -X utf8 -m scripts.probe_qwen_questions --report $report
```

网络阶段要求Windows允许读取网卡信息及绑定实体socket；失败即停止，不回退Clash或其他源。下载包含固定来源及摘要清单；问答使用原生模板、BF16与greedy，Qwen3.5关闭思考，16次输出均已保存。复跑会覆盖本次问答结果，需保留新实验时改用新报告目录。完整结果与限制见 [双模型报告](cases/原模型实测摘要.md)。本次仅文本问答，未测试Qwen3.5图像能力或RKLLM转换。

在教程目录加载工作区路径，再直接使用该环境解释器：

```powershell
. .\scripts\workspace_env.ps1
& ..\.conda\lubanlm-py311\python.exe -c "import torch; print(torch.__version__, torch.cuda.get_device_name(0))"
```

编辑器也应选择这份解释器。项目默认数据和运行目录已指向同级工作区；显式 `LUBAN_DATA`、`LUBAN_RUNS` 和 `CUDA_VISIBLE_DEVICES` 继续优先生效。环境验收使用GPU 0，不静默回退CPU。

## 验收内容与边界

安装入口先检查依赖一致性，再验证CUDA矩阵运算、BF16、SDPA和只作用于独立小张量的Fused AdamW更新。随后以本地Tokenizer分别加载现有Base last、SFT best与SFT last，按固定提示最多生成24个新Token，记录原始输出与停止原因。

检查点和Tokenizer在前后计算SHA256，原模型不更新，不启动训练，不写旧GPU训练账本。网络前后快照应一致，下载连接均记录实体网卡索引及源地址。生成成功只证明迁移后可加载并计算，不能说明中文回答能力已经可靠。
