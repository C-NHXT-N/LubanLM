## 已经会答，为什么换一种问法又失败

v5的60道开发题合格53道，相关可读57道，循环1道；身份10/10、算术9/10。随后第一次独立验收只合格37/60，日常与概念各4/10，算术6/10。五道基础题4/5，采样稳定性通过。程序拒绝导出，闭环仍未完成。原始回答和逐题理由见 [验收报告](50M聊天验收报告.md)。开发题高分不能替代独立验收，反复看同一开发题还有选择偏差。

例如v5在开发检查中正确解释键盘，但对另一种表达可能复述电脑用途；这只是失败证据，不能把该验收问题及其标准回答放进下一轮训练。本次v6构造程序仅读取原v5数据，不读取验收输出；新一轮独立题在修正训练前固定保存。

v4还有明确的能力偏移。同一公共问答验证集的损失由v3的3.660升至v4的5.471，而基础模板与算术损失下降。公共独立样本由约3.5万压到3,666，自编短任务重复八次并训练六轮。数据覆盖与训练强度同时改变，因此不能把退化完全归于某一个参数。

训练记录的样本数也容易误读。v3自编样本仅占监督Token的5.76%；v5算术占样本约14.3%，但只占监督Token约2.78%。当前每条回答的长度不同，Token平均损失不等于各任务获得相同比重；这些占比也不能直接称为梯度贡献。

## 一个回答边界会改变训练输入

推理提示以`助手：`结束。旧编码把提示、回答与EOS一次分词，回答从`《`开始时可能得到跨边界Token`：《`。按字符偏移屏蔽提示后，这个Token没有被监督，而且训练输入不再以推理提示的Token序列开头。

v5的30,806条独立训练样本中有662条受影响，约2.15%。它是实际缺陷，但不足以独自解释全部失败。新版本分别编码提示和回答，再拼接EOS：

```python
prefix_ids = tokenizer.encode(prompt(user), add_special_tokens=False).ids
answer_ids = tokenizer.encode(answer, add_special_tokens=False).ids
input_ids = prefix_ids + answer_ids + [eos_id]
labels = [-100] * len(prefix_ids) + answer_ids + [eos_id]
```

这样第一个回答Token就在真实推理前缀之后被预测。拼接后不要求等于整段文本的规范BPE切分，但必须能还原回答、保证提示ID完全一致。默认旧编码`legacy-joint-v1`保留给旧实验复现；新数据显式选择`prefix-stable-v1`，不能直接作为旧训练的普通resume。

新v6只重新编码既有语义样本，不按最终题增添答案。训练30,299条、验证1,749条，去掉12条内嵌控制符或角色标记与1条同文固定题；全部前缀核查通过。680条旧编码不一致统计覆盖的是保留的训练加验证，分母不同，不能与662条训练侧统计混用。OASST树、问题家族和抄写负载分别隔离。部分移入验证的家族曾被祖先权重看过，因此这套损失验证仍不是独立能力验收。

## 先比较目标，再考虑补充Base

两个候选均从v5不可变权重开始，使用同一个v6数据、相同2000步、学习率1e-5与微批次8。每批2条公共问答，问候、身份、日常、概念、指令、算术各1条。A使用Token平均损失；B先对每条回答的监督Token归一化，再按任务加权：公共30%、算术20%，其余各10%。只改变损失目标，不自动按大批次提高学习率。

完整验证保留manual注意力和微批次2，同时记录各任务损失与宏平均。另存中间最佳候选，开发题语义评分用于选模型，最后权重不再自动等于最好权重。训练检查点记录父路径、SHA256与监督Token链；v5之前的已核查链为5,776,672个监督Token，不包含阶段probe或性能短测。

前缀边界样例、HF与原生提示一致、组批与预取消费游标、跨epoch恢复均已通过。真实磁盘恢复后权重、Adam、随机状态与样本游标一致，非有限损失会拒绝更新。新任务目标与参考计算的损失差、裁剪后梯度最大差均为0。证据见 [修复检查](run-results/chat-v2/correction_checks.json) 与 [任务目标检查](run-results/chat-v2/task_objective_check.json)。

若这组清洁SFT仍不能泛化，才在原预算内补充Base。当前4亿Token来自约2.33亿编码Token的百科语料，有放回窗口抽样，不能称为4亿独立语料。百科语言与对话不同，预训练不足是待验证假设；不能保证补到某个Token数便自动通过。架构、32k词表与4060Ti保持不变。

## 训练速度的第二次核查

首次性能优化已使预训练短测提高4.89倍、SFT提高约5倍。此次进一步比较见 [附录D](../附录/附录D%20训练性能诊断与优化.md)。在相同1024条语义数据上，预取和分桶未达到新增15%吞吐门槛，均不启用；分桶降低padding没有转化为明显提速。

profiler三步内有2442次`to`、1761次乘法和1830次转置，支持继续排查零散算子与主机调度；其中包含GPU内部精度转换，不能全部解释成PCIe传输。组批实测只约0.7%时长，增加CPU加载线程难以解决主要限制。

所有检查与训练均计入原1440分钟总账，预训练1200分钟、SFT含probe180分钟，保留最终验收余量。等待完整人工评分时控制器正常退出并释放锁与临时保活，未评分不会被算作通过。没有恢复定时检查。

## v6受控对照的实际结果

新开发题在修正训练前固定，与原开发题不同。两个候选的起点权重在新题上同为42/60；2000步后，Token目标与任务加权目标都为45/60。每组处理1,412,088个含padding输入位置、811,927个非填充输入位置与234,135个监督Token，样本与步数完全相同。不能把旧开发88.3%与新开发75%直接比较成能力下降。

Token目标末次循环5/60，任务加权末次循环3/60；后者日常5/10，仍未过全部门槛。因此按合格率相同、循环较少的顺序，选择任务加权末次权重继续一个最多30分钟、计划6000步的新阶段，宏平均验证连续两次没有至少0.02改善便停止。训练与中间最佳权重都保留，随后完整审阅实际回答；若仍不能达标，才运行同语料的受控Base延长与两组匹配短SFT。
