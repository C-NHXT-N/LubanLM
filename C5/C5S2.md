# 5.2 Optimizer 与 Learning Rate

> 2026-10-16 路线更新：50M 已完成 5B Token 预训练及一轮 SFT，作为从零训练的教学案例保留；现有结果未证明可靠通用问答能力。第7章起转向成熟模型 LoRA 微调与部署，扩容另作可选实验。当前状态见 [项目状态](../PROJECT_STATUS.md)。

上一节已经得到梯度。现在设一个参数 `w=2`，梯度为 `0.4`，学习率为 `0.1`。最简单的更新会把它变成 `2-0.1×0.4=1.96`。梯度给出变化方向和尺度，学习率决定这一步实际走多远。学习率过大可能越过较好的位置，过小则让有限时间内的改善很慢。

语言模型包含数千万到数亿个参数，各参数的梯度尺度也会不同。本课程使用 AdamW，它为每个参数保留过去梯度的指数移动平均和平方梯度的指数移动平均，再据此调整更新尺度。可以把它理解为：当前梯度不是孤立使用，而是和最近的变化一起决定这一步。

最小构造如下：

```python
import torch

optimizer = torch.optim.AdamW(
    model.parameters(), lr=3e-4,
    betas=(0.9, 0.95), weight_decay=0.1, foreach=False,
)
```

这段接在已经创建的 `model` 后面。`betas` 控制两组移动平均保留过去信息的程度。`weight_decay` 是权重衰减，AdamW 将它作为独立的权重缩减项处理。本教学实现对传入的全部参数使用同一衰减设置，没有另外划分 norm 参数免衰减组，复现时要保持一致。`foreach=False` 使用逐参数实现，减少某些更新阶段临时张量的显存负担。

优化器的状态也占内存。即使前向主要用 BF16，参数与 AdamW 的两组状态仍可保留为 float32。训练显存因此不能只用“参数量×2 字节”估算；参数、梯度、优化器状态和中间激活都要计入，第 5.3 节会用实测检查。

训练刚开始时，随机参数产生的梯度还不稳定。预热（warmup）让学习率从较小值逐渐升到设定峰值，之后用余弦曲线下降。本课程前 5% 的计划更新步数用于预热，末尾降到峰值的 10%。以峰值 `3e-4`、计划 100 步为例，第一步用 `6e-5`，到第五步附近达到峰值，再逐渐减小。

可以直接查看实际训练函数怎样计算：

```python
from training.train import schedule

for step in [0, 4, 5, 50, 99]:
    print(step, schedule(step, total=100, base=3e-4))
```

这里 `step` 从 0 开始，它表示已经完成的优化器更新数。一次更新可能包含多个微批次，所以不能把日志中的更新步数直接当作读过的样本数。若微批次 2、梯度累积 4，一次更新通常处理 8 条训练序列。

预训练默认峰值学习率 `3e-4`，SFT 默认 `5e-5`。SFT 从已有 Base 权重继续学习，数据也更少，较小学习率有助于限制每次改变；这些是本次教学运行的起点，不是所有模型都必须采用的标准答案。

查看日志时，要把 loss、学习率和有效 Token 数一起看。一个下降很快的 loss 可能来自反复读取同一小段文本，也可能来自学习率变化；只看某一步的数值无法区分。当前日志记录 `step`、`lr`、`grad_norm`、`input_tokens` 和 `supervised_tokens`，SFT 中后两个计数尤其不同。

断点恢复还必须恢复优化器状态，否则同样的权重会因为移动平均丢失而走出不同路径。第 5.4 节保存这些状态，并检查从中间点继续训练是否与连续运行一致。先在下一节把一批计算安排进 16GB 显存。
