# 5.3 16GB 显存下的训练内存

> 2026-10-16 路线更新：50M 已完成 5B Token 预训练及一轮 SFT，作为从零训练的教学案例保留；现有结果未证明可靠通用问答能力。第7章起转向成熟模型 LoRA 微调与部署，扩容另作可选实验。当前状态见 [项目状态](../PROJECT_STATUS.md)。

> 实验入口：先完成[低成本必修实验](../docs/低成本必修实验.md)。本节大规模数据与50M命令用于历史研究，需要对应的旧数据版本；目录采用workspace_env.ps1设置，使用已激活的原生环境，不是成熟模型LoRA入口。

> 本节保留0.5B历史短基准，用于解释内存成本；不要求读者正式预训练0.5B。成熟模型LoRA的可训练参数和激活开销需要另测，不能直接套用本节显存结果。

模型可以在 GPU 上前向，不表示它一定能完成训练。前向只需要权重和中间值；训练还要保留反向所需的激活、梯度和 AdamW 状态。现有 0.5B 候选约有 4.89 亿参数，仅四份 float32 的参数相关存储就约需 7.3GiB，还没有加激活、输出 logits 与临时工作区。这是粗略估算，实际占用以完整更新步测量。

教材基准的实际GPU是RTX5060Ti 16GB，历史4060Ti基准保留其原始硬件标签。`workspace_env.ps1`默认选择逻辑设备0；多卡电脑可预先设置CUDA_VISIBLE_DEVICES。筛选后进程内的cuda:0不一定是系统列表的第0张卡，先验证设备与实际计算：

```powershell
. .\scripts\workspace_env.ps1
python -m scripts.verify_gpu
```

验证程序检查CUDA与实际张量运算，不要求旧GPU名称或UUID。这里需已激活原生GPU环境；CPU必修实验有自己的入口，不调用该GPU验证器。

混合精度让主要矩阵计算采用较短的浮点格式，同时让参数与必要的累加保持较高精度。本机支持 BF16，因此优先使用：

```python
with torch.autocast("cuda", dtype=torch.bfloat16):
    logits = model(x)
    loss = F.cross_entropy(logits.float().flatten(0, 1), y.flatten())
```

BF16 是一种 16 位浮点格式，动态范围较宽；它节省部分激活存储和计算开销，但没有把整套 AdamW 状态自动压成两字节。若设备不支持 BF16，主训练循环改用 FP16 与梯度缩放器，降低小梯度下溢风险。本次 BF16 分支仍检查损失与梯度是否有限。

接着缩小一次送进模型的微批次。微批次 1、累积 4 表示先处理一条序列，反向传播，再处理下一条，共累计四次后更新一次。预训练窗口长度相同时，四份平均损失可以除以 4；SFT 回答长短不同，程序按每个微批次实际监督 Token 数加权，保证整体目标仍是对所有回答位置取平均。

梯度检查点（gradient checkpointing）减少反向前保留的激活。它在反向时重新计算一部分前向结果，换来较低显存和额外耗时。本课程按完整 Decoder Block 重算，使用 `use_reentrant=False`；训练时不保存 KV cache，两种状态不能同时启用。梯度一致性检查会比较开启前后得到的每个参数梯度。

梯度裁剪把整体梯度范数限制为 1.0，避免某一步过大的更新。它不会把 NaN 修成正常值，程序仍以 `error_if_nonfinite=True` 检查异常。FP16 分支先解除梯度缩放，再裁剪，以免对缩放后的数值使用错误阈值。

真实 0.5B 基准运行：

```powershell
python -m benchmark.train_benchmark --config .\configs\config_0.5b.json --warmup 3 --steps 10
```

它执行反向传播和 AdamW 更新，包含优化器状态首次分配。默认序列 256、微批次 1、累积 4、BF16 与检查点；若显存不足，依次尝试 128、64，并把失败配置一起记录。不能用成功的 256 长度推断 2048 一定能训练，也不能把 50M 显存结果写成 0.5B 的结果。

本课程手写注意力，不额外引入 FlashAttention、`torch.compile` 或第三方训练框架。首先测清当前实现的成本，再决定后续优化是否值得。具体速度、峰值分配显存和缓存显存见 [实跑报告](../docs/Windows实跑报告.md)，下一节把这些数字转成可以接受的训练预算。
