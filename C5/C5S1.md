# 5.1 从 Next Token Prediction 到 Loss

> 2026-10-16 路线更新：50M 已完成 5B Token 预训练及一轮 SFT，作为从零训练的教学案例保留；现有结果未证明可靠通用问答能力。第7章起转向成熟模型 LoRA 微调与部署，扩容另作可选实验。当前状态见 [项目状态](../PROJECT_STATUS.md)。

第 4 章已经能取出 `[B,T]` 的输入与目标。先只看一条短序列：输入 `[11,28,35,9]`，目标 `[28,35,9,2]`。模型在位置 0 看见 ID 11，输出对整个词表的分数；这一行要和目标 ID 28 比较。后面三个位置重复同样的动作，就组成一次训练的四个预测任务。

分数叫 logits，它们可以是任意实数，还不是概率。假设教学词表只有三个候选，下一个 Token 的正确 ID 是 0：

```python
import torch
from torch.nn import functional as F

logits = torch.tensor([[2.0, 0.0, -1.0]])
target = torch.tensor([0])
probability = logits.softmax(dim=-1)
loss = F.cross_entropy(logits, target)
print(probability)
print(loss)
```

三个概率约为 `[0.8438,0.1142,0.0420]`，总和为 1。正确答案的概率是 0.8438，损失约为 0.16985。损失用一个数表达模型给正确答案的支持程度：正确答案概率越接近 1，损失越接近 0；如果模型把概率分给了别的 ID，损失会增大。

对一个位置，交叉熵可以写成：

$$
\ell=-\log p_y,\qquad p_j=\frac{\exp(z_j)}{\sum_{k=0}^{V_{vocab}-1}\exp(z_k)}
$$

这里 `z` 是长度为 `V_vocab` 的 logits 向量，`y` 是正确 Token ID，`p_y` 是该 ID 对应的概率。求和遍历词表候选，不遍历时间位置。`log` 使用自然对数。PyTorch 的 `cross_entropy` 直接接收 logits，并在内部稳定地计算 log-softmax；不要先做 softmax，再把概率传进去。

真正的模型输出是 `[B,T,V_vocab]`，标签是 `[B,T]`。我们把前两维合并成 `B×T` 个预测位置：

```python
# scores 来自 model(x)，labels 来自 ids[:, 1:]。
loss = F.cross_entropy(
    scores.float().reshape(-1, scores.shape[-1]),
    labels.reshape(-1),
    ignore_index=-100,
)
```

这不是把文章的内容混在一起，而是把每个位置排成一行，方便同一个函数处理。最后一维仍然是完整词表。`float()` 让损失部分用 float32 计算；`-100` 表示当前位置不参与计分，普通预训练窗口没有这种忽略标签，SFT 的问题和 padding 会使用它。

一次参数更新接着执行三个动作：清空旧梯度、反向传播、由优化器更新权重。梯度描述“损失对某个参数的变化率”，并不是一个已经更新好的参数值：

```python
optimizer.zero_grad(set_to_none=True)
scores = model(x)
loss = F.cross_entropy(scores.float().flatten(0, 1), y.flatten())
loss.backward()
optimizer.step()
```

`backward()` 沿前向计算形成的依赖关系，把输出损失的变化传回各层。Embedding、注意力投影、前馈层和归一化缩放参数都会收到梯度。反向传播不需要我们为每层手写求导，但必须保证张量仍在计算图中；把 `loss.item()` 得到的普通数字拿去反向传播就会失败。

上面是便于理解的最小循环，完整实现还包括混合精度、梯度累积、验证和保存，见 [train.py](../training/train.py)。它明确使用 `x=ids[:,:-1]`、`y=ids[:,1:]`，`LubanLM.forward` 不再位移一次。多位移一次会把“下一 Token”变成“隔两个位置的 Token”，即使程序没有报错，学习目标也已经错了。

先运行 `python -m scripts.basics` 可以复算交叉熵，再运行 `python -m scripts.verify_gpu` 检查有限损失、反向传播与参数变化。损失可以下降只能说明当前目标得到改善；短样本上的过拟合不能证明模型掌握一般语言知识。下一节控制每一步怎样移动参数。
