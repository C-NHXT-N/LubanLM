# 5.4 Checkpoint、日志与训练规模估算

> 2026-10-16 路线更新：50M 已完成 5B Token 预训练及一轮 SFT，作为从零训练的教学案例保留；现有结果未证明可靠通用问答能力。第7章起转向成熟模型 LoRA 微调与部署，扩容另作可选实验。当前状态见 [项目状态](../PROJECT_STATUS.md)。

> 实验入口：先完成[低成本必修实验](../docs/低成本必修实验.md)。本节大规模数据与50M命令用于历史研究，需要对应的旧数据版本；目录采用workspace_env.ps1设置，使用已激活的原生环境，不是成熟模型LoRA入口。

训练一次中断后，首先要回答“接下来从哪里继续”。只保存模型权重可以恢复推理，却不能完整恢复训练：AdamW 的历史、学习率位置、数据采样状态都会丢失。因此本节把训练状态保存成检查点（checkpoint）。

`train.py` 保存模型配置与权重、优化器状态、混合精度缩放器、更新步数、Token 计数、Python/NumPy/PyTorch 随机状态和数据采样器状态。SFT 还保存当前排列、游标与 epoch；预训练保存用于选择窗口的随机数生成器。Tokenizer 哈希与数据标识用于检查恢复时有没有换错词表或语料。

第一次短跑可以用独立输出目录，避免覆盖正式模型：

```powershell
. .\scripts\workspace_env.ps1
python -m training.train --config .\configs\config_50m.json --steps 4 --minutes 10 --output $env:LUBAN_RUNS\checkpoints\short-check
```

旧短训验证另用 `50m-base` 目录；该实验没有完成模型能力验收。程序拒绝向已有文件的目录重新初始化训练；继续同一次运行必须明确指定 `--resume`。例如从上面第 2 步恢复，保持学习率、批次、累积、长度与总步数不变：

```powershell
python -m training.train --config .\configs\config_50m.json --steps 4 --minutes 10 --output $env:LUBAN_RUNS\checkpoints\short-check-resumed --resume $env:LUBAN_RUNS\checkpoints\short-check\step-000002.pt
```

恢复后的第 3、4 步应该能和原来的连续训练对照。只比较最终 loss 不够，要比较参数与优化器状态；两个路径恰好损失相近，也可能已经读了不同批次。课程的恢复验证见 [verify_training.py](../scripts/verify_training.py)。检查点只加载本项目产生的可信本地文件，`torch.load` 的训练状态不是通用网页附件格式。

保存先写临时文件，再替换目标文件，减少写到一半留下坏检查点的机会。正式运行保留随机初始化点、几个进度点和 `last.pt`，便于第 6.2 节比较同一提示的输出。到达时间预算前预留校验与保存时间，实际耗时仍要记录，不能把保存时间隐藏掉。

`metrics.jsonl` 每行保存一次观察，包含平均损失、累计输入 Token、累计监督 Token、学习率、梯度范数、速度和峰值显存。`summary.json` 汇总计划步数、实际步数、初始与最终验证损失和停止原因。验证时关闭梯度，采用固定采样；验证 loss 改善反映同来源未参与训练文档上的预测变化，不直接等于聊天质量。

速度单位是 `tokens/s`，表示每秒处理的输入位置数。若实测为 `r`，简单估算可以训练的数量是：

$$
N_{tokens}\approx r\times t_{seconds}
$$

这里 `r` 是当前模型、批次、序列长度与精度组合的训练速度，`t_seconds` 是愿意投入的秒数。24、36、48 小时分别代入 `86400`、`129600`、`172800`。这是按稳定速度外推的估算，未保证包含长时间温度变化、验证和保存等额外成本。

历史50M聊天阶段曾另设24小时预算，其控制器与账本见[历史对照](../docs/50M-SFT历史对照.md)，不作为本版必修任务。新实验使用独立结果目录和明确预算，不继承旧续训承诺。CPU必修实验固定16步；正式GPU实验仍由累计账本限制，到时保存与能力通过分别判断。

`--resume` 用于同一实验的精确恢复，不能修改目标和学习率计划。`--continue-from` 用于开启新的预训练阶段，载入权重与 AdamW 状态，重置新语料采样器和阶段学习率，记录父检查点与累计 Token。两种操作不能混用。

现在有了可恢复、可观察、可限定成本的训练系统。第 6 章用真实的 Tokenizer 和数据正式启动 50M，从随机参数走到一个教学 Base 模型。
